# 已选项目底部清单层设计规格

## 目标

顾客点击页面左下角“已选项目”后，在固定提交栏上方打开一个紧凑的底部清单层，查看和调整当前选单。清单始终表达“预计金额”，最终账单仍以门店为准。

## 交互

- 点击底栏左侧摘要打开清单；点击遮罩、关闭按钮、系统返回或键盘 Escape 关闭。
- 弹层最大高度约为视口的 55%，固定提交栏保持可见且可以继续提交。
- 主项目、局部调理和赠饮均提供“修改”；收费或免费加项的“修改”进入所属主项目详情。
- 每个具体条目均可直接删除。删除主项目时，同时清理该项目的偏好和挂载加项；独立局部调理不随泡脚主项目删除。
- 删除后项目数、已生效减免和预计合计即时重算；删除最后一个条目时自动关闭弹层和底栏。
- 已提交或门店锁定后的只读状态只展示清单，不出现修改和删除操作。
- 修改页关闭或保存后返回清单层，保持顾客的操作上下文。

## 内容层级

- 标题：“已选项目 · N项”，右侧关闭按钮。
- 主项目一行展示名称、偏好摘要和当前身份预计价；加项缩进展示在所属项目下。
- 局部调理按独立服务单位逐项展示，便于单独删除。
- 免费茶饮展示“赠饮”，免费加项展示“免费”。
- 只有减免已经生效时才出现浅绿色减免区，例如“泡脚组合减免 -¥39.9”；未达到条件时不展示凑单提示。
- 底部显示“预计合计”、当前价格身份和“最终以门店账单为准”。

## 视觉与动效

- 内容面使用纯白；深绿作为主操作色，浅翠绿作为已生效减免背景，暖金只用于价格。
- 沿用现有 H5 字体、圆角、描边和图标库，不增加新依赖或视觉资产。
- 弹层即时出现和消失，不添加转场动画；只保留项目既有的 toast 淡入淡出与卡片点击微反馈。

## 数据与业务边界

- 清单来源于当前本地选单状态，金额复用既有预览计价与服务器同步结果。
- 泡脚组合减免必须由既有计价函数判定为已达成后才能显示。
- 前端金额均为预计，不产生线上支付或支付按钮。
- 修改和删除只在 `canEditSelection` 允许的状态执行，不能绕过门店确认后的只读约束。
