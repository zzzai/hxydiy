## 1. 验收结论规则

本清单用于真实手机、微信浏览器和门店测试服务单验收。单元测试、生产构建、CI、公网 HTTP 200 或发布成功都不能替代本清单。

结论只允许：

- `通过`：全部必测项有现场证据且没有阻断问题。
- `有条件通过`：只有不影响数据、安全和主流程的轻微展示问题，并有负责人和修复时间。
- `不通过`：任一必测项失败、没有可信测试身份、出现越权/数据混淆、记录丢失或微信主流程不可用。

禁止使用真实顾客健康信息。使用独立测试门店、脱敏测试顾客、测试技师和可回收测试服务单。

## 4. 微信浏览器主流程

### 4.1 打开与布局

- [ ] 从技师端本人已完成的测试服务进入“记录身体相关情况”。
- [ ] 页面标题、服务位、四步进度和“只记顾客自述，不作诊断”完整可见。
- [ ] 390×844 下无横向滚动；底部按钮不被微信工具栏或技师端导航遮挡。
- [ ] 字体放大一档后关键信息不重叠，按钮仍可点击。
- [ ] 返回、关闭和再次进入行为明确，不误丢已保存记录。

### 4.2 点位选择

- [ ] 正面选择顾客本人右肩，底部显示“右肩”，左右没有镜像颠倒。
- [ ] 正面选择顾客本人左膝，底部显示“左膝”。
- [ ] 背面选择上背和右臀，部位、侧别和人体面对应正确。
- [ ] 再次点击已选点位可取消；底部条目同步删除。
- [ ] 编辑底部条目后，人体选中态仍保持一致。
- [ ] 第四个点位无法加入，并显示“最多记录 3 个部位”。
- [ ] 所有点位触控区域易点中，滚动页面时不会误选。

### 4.3 四步记录

- [ ] 未选择部位不能进入下一步。
- [ ] 每个点位均能选择顾客自述情况、当前状态和本次处理。
- [ ] 字段未完整时不能完成，并准确提示缺失内容。
- [ ] 选项中不出现疾病、诊断、药名、治疗或疗效文案。
- [ ] 完成两个点位后，摘要分别对应，不发生内容串位。
- [ ] 删除其中一个条目后，另一个条目内容不改变。
- [ ] 返回上一步修改，最终摘要与修改结果一致。

### 4.4 顾客确认与保存

- [ ] 未选择“顾客已确认”时，只按未确认规则保存，不进入长期画像。
- [ ] 选择“顾客已确认”后，保存成功只生成一条记录。
- [ ] 连续快速点击保存不会生成重复记录。
- [ ] 保存失败显示真实失败状态，不能显示“成功”或清空草稿。
- [ ] 恢复网络后使用原幂等键重试，最终仍只有一条记录。
- [ ] 保存后重新进入历史，点位、情况、状态和处理与提交一致。

## 5. 查看上次

### 5.1 会员或可信登录顾客

- [ ] 同店下一次有效服务只显示最近一条已确认安全摘要。
- [ ] 身体信息仅显示“身体情况：服务前再确认”，不显示具体病情、原话或诊断词。
- [ ] 过期、被更正和未确认记录不作为当前有效摘要。
- [ ] 服务结束或失去当前服务权限后不能继续读取。

### 5.2 匿名顾客

- [ ] 同一服务端匿名顾客主体且仍有合法服务关联时，可读取允许的安全摘要。
- [ ] 换设备或清除浏览器数据后，不错误识别为原顾客。
- [ ] 两个匿名测试顾客在同一门店的记录不会串联。
- [ ] 匿名顾客可信登录但未主动确认合并时，历史不自动并入会员档案。
- [ ] 完成确认合并后，只合并该匿名主体的可证明记录，且留有审计。

## 6. 权限与隔离

- [ ] 其他技师不能为不属于自己的服务补写或修改身体记录。
- [ ] 同一技师不能为其他门店服务写入或查看记录。
- [ ] 店长权限不会自动获得技师本人服务写入能力。
- [ ] 伪造服务单、顾客、门店、版本或点位编码均被后端拒绝。
- [ ] 技师端不显示手机号、消费金额、顾客价值等级、营销标签或完整健康历史。
- [ ] 管理端客户列表、搜索和导出不出现身体明细。
- [ ] 审计只记录操作者、门店、服务、字段编码和结果，不记录敏感正文。

## 7. 弱网、异常与兼容

- [ ] 飞行模式下保存失败可理解，恢复网络后可安全重试。
- [ ] 保存过程中切到后台再返回，不重复提交、不覆盖新结果。
- [ ] 微信拒绝权限、页面刷新、登录过期均给出可执行提示。
- [ ] v1 至 v4 历史页面仍能打开，不显示原始 JSON 或白屏。
- [ ] v5 未知字典值安全降级，不把编码直接展示给一线人员。
- [ ] 同一服务同时由两个页面提交时，后端保持幂等并给出明确结果。
