# 服务位短链接迁移与回滚说明

更新日期：2026-09-23

## 影响范围

- 新增 Alembic revision：`20260923_qr_short_code`。
- 仅为 `service_position_qrs` 增加可空的 `short_code_hash` 字段及唯一索引。
- 不回填、不轮换、不停用、不换绑现有二维码记录；现有记录只会在授权管理端读取二维码链接时惰性补写哈希。
- 不修改顾客、会员、选单、订单、评价、价格或服务位占用数据。

## 发布前验证

1. 对生产库执行 `pg_dump -Fc`，并校验 SHA-256。
2. 将备份恢复到隔离数据库，在隔离库执行 `alembic upgrade head`。
3. 验证 Alembic head 为 `20260923_qr_short_code`，字段可空、索引唯一，既有二维码记录数量和状态不变。
4. 隔离库升级成功后，才允许生产库执行同一迁移；随后发布精确主干提交并检查健康接口和短链接路由。

`deploy/diy/deploy-production.sh` 的显式迁移清单只批准
`20260923_service_position_qr_short_code.py`。清单外新增迁移或任何迁移删除仍会被门禁拒绝。

## 回滚策略

- 应用发布失败时由发布脚本恢复上一 release；数据库迁移不自动降级，避免在未知写入后删除字段。
- 若确认尚未生成任何短码哈希，可执行该 revision 的 downgrade，删除唯一索引和字段。
- 若已经生成短码哈希，优先恢复应用并保留新增字段；确需数据库回滚时，先备份并确认短链接已停止使用，再单独审批 downgrade。
