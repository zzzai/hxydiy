# 店长评价闭环 PRD · 2026-10-26

## 业务目标
紫薇壹号店顾客可通过服务单或无座位评价二维码反馈。店长在同一个企微工作台看到两类评价，点通知到对应评价，保存跟进后能重新读取；不能因为入口不同漏掉独立扫码意见。技师权限不扩大。

## 已确认问题
1. 独立扫码 `/visit-feedback` 已保存成功，但未安排任何通知。
2. 手机评价和低分待办固定筛选 service_review，漏掉 visit_feedback。
3. 企微回跳只识别 service_review；两表 ID 相同，原列表 key 仅使用数字。
4. 旧日志只记录通知开始，没有可核对的发送结果。
5. 实际 React 浏览器复现连续点击保存触发两次 PATCH，需同步互斥。

## 本批交互和行为
- 评价页使用现有卡片和详情，不加新的底部导航。两类评价一起展示，详情明确来源。
- 待办由服务器筛选低分且待跟进，避免先取最新若干条再漏掉低分项。
- 通知卡只含门店、来源、评分与“查看评价”；顾客原文、手机号留在已鉴权工作台。回跳参数包含来源类型和正整数 ID，OAuth 前后保留一次，非法或越权链接给出可恢复说明。
- 跟进不能改顾客原文。连续点击只发一次请求，保存失败保留输入，成功后列表及详情回读；两种来源互不影响。
- 新扫码通知默认关闭，待发送范围授权后启用；原服务评价通知保持既有触发范围。
- 只读取新提交产生的事件，不补发历史评价。发送依赖异常不反转已经成功的顾客评价。

## 运营核验
在现有操作记录筛选“企微评价通知”，显示业务语言结果、目标人数、API 受理人数、未受理人数。结果未知不能当作成功，也不能自动重发。API 受理、真实企微卡片可见和人工阅读是三个不同事实。

## 明确边界
本批不增表，不启用新群发、顾客消息、营销或权限，不改原评价和历史会员资料。进程内任务在重启时可能中断；本批补齐触发与证据，但不声称有跨重启可靠送达。后续持久 outbox 单独设计及确认数据库范围。

## 验收
- 合成提交成功并回读；相同幂等键重试不增加通知。
- 两店隔离，撤销绑定、过期员工、技师、跨企业和多工作区冲突不发送。
- provider 接收、部分接收、全拒绝、超时、畸形响应、无接收人、审计失败分别覆盖。
- 两类同号、OAuth 回跳、越权失败、保存回读、双击互斥、失败恢复通过真实组件浏览器验证。
- 无真实企微消息、无生产数据写入；真机由人完成。
