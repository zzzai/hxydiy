# BR-01 工作台与异常中心 PRD

关联：[README](README.md)、[order-settlement](order-settlement.md)、[analytics-metrics](analytics-metrics.md)
优先级：P0/P1
当前实现：部分（今日工作台、店长移动端待处理）

## 1. 执行摘要

为门店店长和总部运营提供一个“今天需要处理什么”的工作台，把订单、服务位、评价、加选、超时和冲突统一成有负责人、有时限、有处理结果的异常队列。

## 2. 问题与目标

- 店长在门店现场无法从大量订单中快速找到需要动作的异常；
- 总部看不到跨店异常的总量和责任分布；
- 现有工作台混合今日统计、在店流和待处理，口径不一致；
- 移动端与桌面端操作契约不一致。

目标：

- 3 秒内回答“今天有没有必须处理的事”；
- 异常按严重度、时长、责任人排序；
- 任何异常都能从工作台进入处理对象；
- 关闭异常必须记录原因和处理人。

## 3. 角色与范围

| 角色 | 可看 | 可操作 |
|---|---|---|
| 总部管理员 | 全品牌异常汇总、门店排名、跨店明细 | 分派、升级、关闭（需理由） |
| 店长 | 本店异常 | 处理本店可处理项、升级 |
| 店员 | 本店现场只读待办 | 不可关闭需店长处理的异常 |
| 技师 | 本人相关提醒 | 不可操作店长异常 |

## 4. 异常对象

统一异常模型：

```text
id
type: stale_order / position_conflict / addon_pending / low_review / payment_exception / notification_failure
scope: brand / store / technician
severity: critical / high / normal
owner_staff_id
created_at
due_at
status: open / acknowledged / resolved / dismissed
resolution_code
resolution_note
audit_ref
```

首版支持：

- 超时未开始订单；
- 服务位冲突；
- 加选待确认；
- 低分评价待跟进；
- 企微通知失败（P1）；
- 结算异常（P1）。

## 5. 核心流程

### 5.1 店长进入工作台

1. 默认显示本店、当前营业日；
2. 顶部显示今日订单、服务中、待结账、需处理；
3. “需处理”按总数和严重度展示；
4. 点击进入异常列表，不是全部订单列表。

### 5.2 异常处理

1. 打开异常详情：对象、发生时间、持续时间、负责人、关联订单/评价/服务位；
2. 选择“处理完成 / 无需处理 / 升级”；
3. 必填处理说明；升级必须选择接收人；
4. 写审计并刷新工作台。

### 5.3 总部视图

1. 选择品牌/区域/门店；
2. 查看异常总量、按类型分布、门店排名、超时最长项；
3. 可下钻到门店异常明细，但默认只读；
4. 升级/关闭必须记录总部操作人。

## 6. 业务规则与不变量

- 异常数量只统计 `open + acknowledged`，已完成不计数；
- 同一对象同一时刻只能有一条活动异常；
- 异常必须由系统根据权威事实创建，不允许人工手工造单；
- 店长只能处理本店异常；
- “关闭”不等于“已解决”；解决必须选择 resolution_code；
- 关闭后 7 天内可重新打开（P1）；
- 工作台数字与异常列表必须同源；
- 任何异常都需要 created_at、scope、owner 或未分派标记。

## 7. 页面与状态

- 空态：今天没有需处理事项，并解释检查范围；
- 错误：局部错误、重试、数据更新时间；
- 无权限：说明缺什么权限，不显示空白；
- 移动端：单列卡片，最多显示 3 条摘要 + 查看全部；
- 自动刷新：工作台至少 30 秒轮询或手动刷新，必须显示最后更新时间。

## 8. 指标

- 异常总量、按类型；
- 平均首次响应分钟；
- 平均关闭分钟；
- 超时未处理数；
- 异常关闭率；
- 通知点击率（P1）。

## 9. 验收标准

- [ ] 工作台“需处理”与异常列表总数一致；
- [ ] 超时订单、冲突、低分评价能从工作台进入对应对象；
- [ ] 关闭异常必须填写说明并写审计；
- [ ] 店长不能处理其他门店异常；
- [ ] 总部能看到跨店异常汇总；
- [ ] 数据时间范围使用 Asia/Shanghai 营业日；
- [ ] 页面有加载、空、错、无权限、重试。

## 10. 当前实现差距

- 工作台“今日订单/需处理”已经说明历史口径，但三套数据源仍未统一；
- 店长移动端待处理只有超时和低分评价，没有服务位冲突；
- 没有异常对象/负责人/关闭原因模型；
- 没有自动刷新；
- 总部没有跨店异常视图；
- 桌面工作台仍可手工操作订单，与移动端只读契约冲突。

## 11. 非目标与开放问题

非目标：把全部订单搬进工作台。

🔵 OQ：工作台默认营业日还是自然日？建议营业日，需门店确认。
🔵 OQ：异常升级到谁？店长→区域督导→总部，需要组织架构。
🔶 假设：首版异常类型只做超时、冲突、低分评价、加选四种。
