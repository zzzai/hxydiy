## 1. 执行摘要

经营分析的目标是让总部和店长做经营决策，而不是展示一堆数字。每个指标必须有口径、时间范围、数据来源、更新时间和适用范围；没有这些，不允许上线。

## 3. 角色与范围

| 角色 | 范围 | 能力 |
|---|---|---|
| 总部管理员 | 全品牌/区域 | 汇总、排名、下钻、导出 |

| 技师 | 不可见经营金额 | 只看个人服务量/评价（P1） |

## 4. 指标字典（首版）

| 指标 | 定义 | 来源 | 口径/排除 |
|---|---|---|---|
| 实收金额 | 支付金额 - 已退款 | Settlement | 仅 paid/refunded；排除测试 |
| 订单数 | 履约订单数 | ServiceOrder | 排除已取消；按下单时间 |
| 客单价 | 实收 / 有效订单数 | 计算 | 订单数=0 时返回 null |
| 新增顾客 | 首次手机号/到店 | Customer | 按注册/首访时间 |
| 复购顾客 | 统计期内到店≥2次 | Occupancy/Order | 同顾客跨店按品牌合并 |
| 会员转化 | 新办会员/新增顾客 | Membership | 需卡记录 |
| 评价均分 | 评分均值 | Review | 排除已删除；显示评价数 |
| 低分待跟进 | ≤2 分且未关闭 | ReviewFollowUp | 按评价时间 |
| 服务位利用率 | 占用分钟 / 可营业分钟 | Occupancy | 排除停用/停业；容量>1 按工位 |
| 平均服务时长 | 结束-开始 | Occupancy | 仅有效服务；排除异常<1 分钟 |
| 平均离位到释放 | release-depart | Occupancy | 仅完整记录 |
| 加选率 | 有加选订单/订单数 | SelectionChange | 需变更记录 |
| 券核销率 | 已用/已发 | CouponIssue | 按发放期 |
| 异常数 | 活动异常数 | Exception | 已关闭排除 |
| 漏斗 | 进入→查看→选单→提交→评价 | EventLog | 去重匿名 ID |

指标必须展示：

- 时间范围；
- 数据更新时间；
- 分母（如评价数、订单数）；
- 无数据 vs 0 的区别；
- 当前门店/品牌范围。

## 5. 数据质量规则

- 负数金额/退款超支付 → 异常，不展示；
- 服务时长 < 1 分钟或 > 12 小时 → 标记异常；
- 服务结束早于开始 → 排除并告警；
- 停用位置/停业时段不计入利用率；
- 评价无关联订单 → 单独标记；
- 匿名/未登录顾客不计入复购；
- 测试门店/测试数据必须排除；
- 接口返回 `null` 表示无数据，`0` 表示真实为零。

## 6. 核心流程

### 6.1 店长查看

1. 默认本店、最近 7 天；
2. 切换日期范围；
3. 查看核心指标、趋势、项目热度、评价；
4. 点击指标查看明细（P1）；
5. 导出需权限。

### 6.2 总部查看

1. 选择品牌/区域/门店；
2. 汇总卡 + 门店排名；
3. 下钻到门店；
4. 对比同比/环比（P1）；
5. 导出。

### 6.3 数据异常

1. 指标计算跳过异常记录；
2. 页面显示“N 条记录未纳入，原因…”；
3. 监控告警；
4. 运营可下钻修正。

## 7. 权限与审计

- 店长只看本店；
- 总部跨店需显式选择范围；
- 导出含顾客/金额时审计；
- 指标定义变更需版本；
- 数据修正需审计。
