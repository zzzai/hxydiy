# BR-03 服务位与房间 PRD

关联：[README](README.md)、[order-settlement](order-settlement.md)
优先级：P1（现有基础较完整）
当前实现：较完整（看板、房态、配置、扫码占位）

## 1. 执行摘要

服务位是门店现场履约的核心资源。系统必须让店长在 5 秒内判断“哪些位置可用、谁在用、为什么冲突”，并保证服务位状态与订单/服务记录一致。

## 2. 问题与目标

- 现场存在“已入座但系统空闲”“服务结束未释放”“多人抢位”；
- 房间/床位/沙发配置不统一；
- 保洁和检查没有责任人；
- 叫号/排队与选单未打通。

目标：

1. 服务位状态与履约状态强关联；
2. 冲突可见、可处理、可审计；
3. 房间配置版本化，避免历史数据被覆盖；
4. 扫码占位与人工安排一致。

## 3. 角色与范围

| 角色 | 查看 | 操作 |
|---|---|---|
| 店长 | 本店全部服务位 | 安排、释放、标记保洁、处理冲突 |
| 店员 | 本店房态 | 安排/释放（需授权） |
| 技师 | 本人服务位 | 开始/结束服务，不改房态配置 |
| 总部 | 跨店房态汇总/配置模板 | 维护类型/容量/模板，不直接操作单店 |

## 4. 业务对象

### Position

```text
id, store_id, code, name, type, floor, zone,
capacity, sort_order, status: enabled / disabled,
config_version, created_at, updated_at
```

### Occupancy

```text
id, position_id, store_id, selection_session_id, order_id,
customer_id, technician_id,
status, held_at, started_at, service_end_at, departed_at, released_at,
release_reason, version
```

### 保洁/检查任务（P1）

```text
id, position_id, type: cleaning / inspection,
assignee_staff_id, status, started_at, completed_at, note
```

## 5. 状态机

```text
available
  → held（顾客选座/预约）
  → waiting_service（已确认，等待技师）
  → in_service
  → post_service_present（服务结束，顾客未离位）
  → cleaning
  → released
```

异常：

```text
any active state → conflict（重复占用/超时未变）
conflict → resolved / released
```

规则：

- 同一服务位同一时刻只能有一个 active occupancy；
- `released` 只能由系统或授权店长触发；
- 服务结束 ≠ 服务位释放；
- 顾客离位后进入 cleaning；清洁完成后 released；
- 强制释放必须写原因和审计；
- 配置停用不删除历史占用。

## 6. 核心流程

### 6.1 安排

1. 店长从待安排选单中选择顾客；
2. 系统推荐可用服务位（按类型/楼层/容量）；
3. 店长确认，创建 occupancy；
4. 系统通知技师；
5. 技师开始服务。

### 6.2 服务中

- 服务结束由技师动作触发；
- if 顾客仍在位 → post_service_present；
- if 顾客离位 → cleaning；
- 清洁完成 → released。

### 6.3 冲突

1. 系统检测同一位置重复占用/状态超时；
2. 生成异常，冻结该位置的新安排；
3. 店长选择：保留哪一个、释放哪一个、补偿方案；
4. 写审计，恢复可用。

### 6.4 扫码占位

1. 顾客扫位置码；
2. 系统校验门店/位置/选单；
3. 生成 held 占用，超时自动释放；
4. 店长可取消/改派。

## 7. 硬规则

- 房态页数字必须与 occupancy 活动记录一致；
- 服务结束时间必须晚于开始时间；
- 释放时间必须晚于离位时间；
- 不允许删除位置，只能停用；
- 位置编码门店内唯一；
- 位置类型变更不回溯历史；
- 设备/扫码绑定必须校验门店归属；
- 所有状态变更带 version，防并发覆盖。

## 8. 权限与审计

- 店长：本店安排/释放/冲突处理；
- 店员：按授权安排/释放；
- 技师：本人服务开始/结束；
- 总部：查看、维护模板；
- 强制释放、改派、删除配置必须审计。

## 9. 指标

- 服务位利用率；
- 平均占用时长；
- 平均离位到释放时长；
- 冲突数/冲突解决时长；
- 保洁完成时长（需记录开始）；
- 空置率按区域/时段。

口径注意：

- 利用率 = 有效占用分钟 / 可营业分钟，不把停用位置计入分母；
- 多床位/多工位按 capacity 计算；
- 需排除测试数据、停业时段。

## 10. 验收标准

- [ ] 房态看板与 occupancy 活动记录一致；
- [ ] 安排/开始/结束/保洁/释放形成闭环；
- [ ] 冲突可检测、可处理、可审计；
- [ ] 停用位置不影响历史数据；
- [ ] 扫码占位校验门店和选单；
- [ ] 桌面与移动端房态一致；
- [ ] 利用率口径有说明并排除停业/停用。

## 11. 当前实现差距

- 房态页已展示 17 个位置，6 卡摘要已改为自适应；
- 保洁开始时间未记录，清洁耗时暂不可计算；
- 冲突处理主要是展示，缺完整处理动作和审计；
- 扫码占位与人工安排的并发保护需验证；
- 总部无跨店房态汇总；
- 服务位利用率口径仍为 0%，需按营业时段/容量修正。
