# BR-07 顾客、标签、分群与评价运营 PRD

关联：[README](README.md)、[customer-service-feedback-prd.md](../customer-service-feedback-prd.md)、[admin-membership-closure-prd.md](../admin-membership-closure-prd.md)
优先级：P1
当前实现：顾客列表/会员/评价基础可用；标签、分群、跟进历史不完整

## 1. 执行摘要

顾客运营的目标不是“存手机号”，而是让店长/技师在服务前后知道：这是谁、来过几次、偏好什么、上次评价如何、现在该不该跟进。

## 2. 问题与目标

- 顾客标签通过弹窗添加，但标签库/归属/审批不清；
- 分群规则是原始 JSON，运营无法自助；
- 评价列表能看，但低分跟进没有完整闭环；
- 手机号展示/查看权限需符合隐私；
- 顾客合并/重复账号没有规则。

目标：

1. 统一顾客身份与门店关系；
2. 标签可运营、可审计、可分析；
3. 低分评价有跟进责任人和结果；
4. 隐私按权限展示。

## 3. 角色与范围

| 角色 | 顾客列表 | 标签 | 分群 | 评价 |
|---|---|---|---|---|
| 总部 | 全品牌/授权范围 | 标签库管理 | 全品牌分群 | 跨店查看/分析 |
| 店长 | 本店 | 本店启用/打标 | 本店分群 | 本店查看/跟进 |
| 技师 | 本人服务顾客 | 打标（需权限） | 无 | 本人服务评价（脱敏） |
| 店员 | 受限 | 无 | 无 | 无 |

手机号规则：

- 默认脱敏；
- 有查看权限的角色可查看完整手机号；
- 查看完整手机号必须写审计，不得批量导出；
- 顾客端登录手机号与后台展示一致。

## 5. 核心流程

### 5.1 顾客识别

1. 顾客手机号登录/到店；
2. 系统按手机号合并身份；
3. 无手机号时使用匿名访客 ID；
4. 合并需保留原记录和审计；
5. 不允许手工删除顾客。

### 5.2 打标签

1. 店长/技师选择顾客；
2. 选择已有标签或申请新标签；
3. 写 assignment（含 store_id/来源）；
4. 标签变更写审计；
5. 顾客端不展示内部标签。

### 5.3 分群

1. 运营选择条件（到店次数、消费、标签、评价、会员）；
2. 预览人数；
3. 保存分群；
4. 定时/手动刷新人数；
5. 用于营销/触达（需 BR-08）。

### 5.4 低分评价跟进

1. 评价 ≤ 2 分自动进入待跟进；
2. 分配店长/责任人；
3. 联系顾客并记录结果；
4. 解决/驳回需理由；
5. 写审计，不修改评价原文。

## 6. 硬规则

- 顾客身份唯一键优先手机号；匿名 ID 不可与手机号合并为同一人；
- 标签必须属于品牌或门店；
- 门店只能使用已启用的品牌标签；
- 分群只读定义，不允许直接改成员；
- 评价原文不可编辑/删除；
- 低分跟进不得承诺未授权的补偿；
- 批量导出手机号需更高权限和审计；
- 合并顾客必须保留原 ID 映射。

## 7. 权限与审计

- 店长本店；总部跨店；
- 查看完整手机号/导出需单独权限；
- 标签库变更总部审批；
- 顾客合并、标签批量、导出、评价跟进全部审计；
- 审计包含前后值、门店、操作人。

## 8. 指标

- 新增顾客、复购率、到店频次；
- 标签覆盖率；
- 分群人数准确率；
- 低分评价首次响应/关闭时长；
- 评价均分、低分率；
- 手机号完整率/重复率。

## 9. 验收标准

- [ ] 顾客按手机号正确合并，匿名身份不误合并；
- [ ] 标签添加有弹窗选择、门店范围、审计；
- [ ] 分群可自助配置并预览人数；
- [ ] 低分评价有负责人、跟进记录、关闭原因；
- [ ] 完整手机号按权限展示并审计；
- [ ] 店长不能看其他门店顾客；
- [ ] 评价原文不可修改。

- 标签库有页面，但归属/启用/审批模型不完整；
- 分群仍是原始 JSON/基础页面；
- 低分评价可看，但跟进闭环和历史不足；
- 手机号完整查看的审计不完整；
- 顾客合并/去重缺失；
- 批量导出未做权限控制。
