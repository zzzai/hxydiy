# BR-05 服务目录、加项、商品与页面发布 PRD

关联：[README](README.md)、[store-lifecycle](store-lifecycle.md)
优先级：P0/P1
当前实现：服务项目/加项较强；商品展示边界未定；页面配置不可达

## 1. 执行摘要

建立“总部标准目录 → 门店覆盖 → 顾客可见版本”的三层发布模型。门店不是复制一份目录，而是在总部标准上做可审计的本地覆盖；顾客看到的必须是已发布版本，而不是编辑中的草稿。

## 2. 问题与目标

### 已确认问题

- 服务项目编码全局唯一但门店需要本地项目，冲突风险；
- 加项与项目关系、价格、适用门店不透明；
- 商品页面存在，但未确认是展示型还是交易型；
- 页面配置有页面但当前导航不可达；
- 发布无版本、无回滚、无生效时间；
- 总部/门店上下架权限边界不清。

### 目标

1. 总部一次维护，多店可控发布；
2. 门店可以停售/调价但不能破坏标准；
3. 顾客看到的价格、项目、页面可追溯到发布版本；
4. 发布失败可回滚。

## 3. 角色与范围

| 角色 | 总部标准 | 门店覆盖 | 发布 |
|---|---|---|---|
| 总部管理员 | 增删改、审批 | 查看 | 全品牌发布 |
| 总部运营 | 编辑草稿 | 查看 | 按范围发布 |
| 店长 | 只读 | 本店停售/启用/本地价（需授权） | 本店页面发布（需审批） |
| 店员 | 只读 | 只读 | 无 |
| 顾客 | — | — | 只看到已发布 |

## 4. 业务对象

### CatalogItem（标准项目）

```text
id, type: project / addon / product / package,
code, name, category_id, description, media[], duration_minutes,
base_price_cents, cost_cents, member_price_cents,
store_scope: all / selected, status: draft / published / archived,
version, effective_from, effective_to
```

### StoreOverride（门店覆盖）

```text
id, store_id, item_id, status: enabled / disabled,
local_price_cents, local_name, local_description,
reason, approved_by, effective_from, effective_to, version
```

### Page（页面）

```text
id, store_id, page_type, title, blocks[], status: draft / published,
version, published_at, published_by, schedule
```

### Product boundary

商品 `product` 首版定位：

- 展示型：只展示图片、名称、说明、价格带、购买入口（外链/到店）；
- 交易型（未确认）：需要库存、订单、履约、退款，不能只加一个“购买”按钮。

🔵 OQ-01 未决前，商品页不得展示“加入购物车/立即购买”等交易承诺。

## 5. 状态与发布

```text
draft → review → published → archived
              └→ rejected
```

发布规则：

- 发布必须生成不可变版本；
- 已发布版本不被编辑，编辑生成新 draft；
- 生效时间可预约；
- 回滚 = 发布历史版本的新版本；
- 门店覆盖只影响本店；
- 发布失败整体回滚，不允许半套目录上线；
- 价格变更需记录前后值和审批人。

## 6. 核心流程

### 6.1 总部发布标准项目

1. 创建草稿；
2. 配置价格、时长、媒体、适用门店；
3. 提交审核；
4. 审核通过；
5. 选择门店范围/生效时间；
6. 发布；
7. 顾客端缓存失效。

### 6.2 门店停售/启用

1. 店长选择标准项目；
2. 设置停售/启用和原因；
3. 若调价，进入总部审批；
4. 生效；
5. 写审计。

### 6.3 页面发布

1. 店长/运营编辑页面块；
2. 预览（桌面/移动）；
3. 提交审核（总部策略）；
4. 发布；
5. 可预约生效/下线。

## 7. 硬规则

- 项目/加项编码全局唯一；门店本地项目使用 `store_id + local_code`；
- 已发布版本不可直接修改；
- 价格不能为负，会员价不得高于原价（除非业务确认）；
- 门店不能上架总部未发布项目；
- 门店覆盖必须引用标准项目；
- 页面必须至少有一个有效区块才能发布；
- 图片/媒体必须校验类型、大小、可访问性；
- 所有发布/回滚/价格变更写审计；
- 删除一律归档，不物理删除。

## 8. 权限与审计

- 总部维护标准；
- 店长只能本店覆盖和页面；
- 本地调价需审批；
- 发布、回滚、覆盖、价格变更全部审计；
- 审计记录包含版本号、前后值、操作人、门店范围。

## 9. 指标

- 标准项目覆盖率；
- 门店停售率/本地调价率；
- 发布成功率/回滚率；
- 页面发布到生效时长；
- 项目浏览→选单转化；
- 目录错误/下架遗漏数。

## 10. 验收标准

- [ ] 总部发布后门店可见；
- [ ] 门店停售只影响本店；
- [ ] 本地调价需审批并留痕；
- [ ] 发布版本可回滚；
- [ ] 未发布项目顾客不可见；
- [ ] 页面配置页可达、可预览、可发布；
- [ ] 商品若为展示型，不出现交易按钮/库存承诺；
- [ ] 编码唯一性在门店/总部范围正确。

## 11. 当前实现差距

- 项目/加项 CRUD 已有，但 master/override 模型不完整；
- 门店本地项目与全局编码冲突未解决；
- 商品页有页面，交易边界未确认；
- 页面内容配置已可访问；总部已提供“操作门店”选择器，选择结果用于读取和保存；
- 已实现页面发布版本历史和一键回滚：每次发布生成不可变快照，回滚会生成新版本并重新发布；仍缺预约生效时间和发布审核；
- 发布审核流程缺失；
- 媒体/价格校验需补。
