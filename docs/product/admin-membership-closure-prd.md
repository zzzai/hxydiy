# 管理端年度会员闭环 PRD（首期）

## 目标与范围

让店长在不绕过顾客本人动态码核验的前提下，完成年度会员的开通、续费、取消/退款、年度赠送权益核销、换机审核和受审计的异常恢复。

首期范围仅覆盖管理端与服务端。顾客端继续负责动态会员码与新设备绑定；技师端继续负责日常扫码核验。后台不得通过手机号、手工勾选或前端改价直接给予会员价。

不包含支付通道对接、支付截图留存、跨门店办理或专用扫码硬件采购。

## 已确认业务规则

1. 开通时记录支付渠道及脱敏流水尾号或人工收据号；店员须确认已向顾客说明并确认权益。服务端固定生成周期起止时间与周期号。
2. 可在到期前 90 天续费。新周期从上一周期到期瞬间开始，不覆盖、也不提前启用旧周期。
3. 每个年度周期的一次赠送，只能核销到一条由服务端判定为“已发布、当前门店、门店价不高于 99 元、无加项”的服务行。确认时原子改价、核销权益并写审计；取消该服务行时释放权益。
4. 取消/退款必须选择原因和退款处置。退款或取消后，未使用赠送权益统一作废；已核销权益不可回退，只允许店长通过受审计的异常恢复流程重开同一周期。
5. 换机采用“顾客申请 → 店长审核 → 撤销旧设备、旧会话和未消费动态码 → 顾客在新设备自行绑定”。
6. 异常恢复仅限店长，必须提供原因、关联周期和幂等键，保留完整审计；不得作为手机号直接启用会员价的替代入口。

## 状态与权限

| 对象 | 状态/约束 | 操作人 |
| --- | --- | --- |
| 会员周期 | scheduled、active、cancelled | 店长创建、续费、取消/恢复 |
| 年度赠送权益 | available、used、voided | 服务端原子流转 |
| 换机申请 | pending、approved、rejected、completed | 顾客申请；店长审核 |
| 服务行赠送核销 | 仅符合资格的当前门店服务行 | 店长确认；取消时释放 |

`used` 是事实记录，取消/退款不将其改回 `available`。异常恢复创建或重新启用同一周期时，必须使用幂等键，不能重复赠送或重复写审计。

## 接口与数据约束

- 管理端命令均由服务端根据登录店长、门店和当前时间计算，前端不得传入任意周期号、起止时间或优惠金额。
- 支付凭证仅保存支付渠道、脱敏尾号或人工收据号；不保存支付截图及完整支付流水。
- 续费命令检查旧周期属于当前门店，且当前时间不早于旧到期前 90 天；新周期起点固定为旧到期时间。
- 赠送核销在一个事务内锁定权益和服务行，重复请求按幂等键返回同一结果；资格不满足时不得改价或核销。
- 服务行取消仅在该行实际占用赠送权益时释放；已退款/取消后被作废的权益不得通过服务行取消重新开放。
- 换机审核必须同时撤销旧可信设备、顾客登录会话版本和未消费动态码；新设备绑定仍由顾客端完成。

## 验收要点

1. 店长可开通会员并查看支付凭证摘要、权益说明确认、周期及审计；非本门店、非店长不能操作。
2. 到期前 90 天外续费被拒绝；窗口内续费生成连续的未来周期，不改变当前周期。
3. 不合资格服务行、跨店服务行、含加项服务行及超过 99 元的服务行均不能核销赠送；成功核销后原子形成改价和审计。
4. 取消/退款必须含原因和处置，未用权益变为 `voided`；已核销权益保持事实，不能由普通取消回退。
5. 同一异常恢复幂等键不会重复创建周期或赠送；没有原因、周期或店长权限的恢复被拒绝。
6. 换机申请审核后旧设备、旧会话和未消费动态码都失效，且后台仍不存在手机号直接套会员价入口。
