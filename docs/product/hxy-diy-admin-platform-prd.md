# 荷小悦 DIY 管理后台与门店运营后台生产级 PRD

## 1. 文档定位

- 版本：v1.0
- 状态：产品基线，进入技术设计与分阶段实施
- 适用范围：总部管理后台、门店运营后台、技师手机 Web；顾客端和智慧宝作为外部协作系统
- 首期规模：单店 17 个服务位（8 个大厅沙发、9 个房间床位）
- 扩展目标：共享架构支持数百至千家门店

## 2. 产品目标

建立一套门店隔离、权限可审计、内容可运营、服务闭环可追踪的 DIY 平台。平台必须让总部集中维护商品与服务项目，让店长根据本店真实情况管理技师、服务位和二维码，让技师快速完成服务确认、结束和顾客画像记录，同时不与智慧宝争夺物理资源控制权。

## 3. 业务边界

### DIY 负责

- 电子菜单、商品、服务项目、价格、规格和内容详情；
- 图片上传、媒体资源和二维码；
- 扫码选位、会员识别、价格计算、选单提交；
- 服务确认、服务结束、评价；
- 技师顾客画像、标签和审计；
- 服务位电子状态以及智慧宝只读状态展示；
- 门店和总部运营报表。

### 智慧宝负责

- 真实开沙发、开房间、派钟；
- 离位、清洁、物理资源释放；
- 真实履约单和物理运营状态。

### 明确不建设

- 预约；
- DIY 派单或自动匹配技师；
- 收款、财务结算和退款执行；
- DIY 清洁执行或物理资源释放；
- 前台、财务、普通员工独立角色。

## 4. 用户角色与权限

### 总部管理员

跨门店管理门店、账号、商品、项目、价格、图片、详情、发布范围、跨店技师授权、报表、导出、审计和争议更正。

### 门店店长

仅访问绑定门店。对商品/项目主数据只能上架、下架；不得修改名称、编码、价格、规格、图片、详情或目录。可以在本店新增、编辑、停用技师，新增、编辑、停用服务位，生成、替换、作废二维码，确认/结束服务，维护本店画像并处理受控更正。

### 技师

具有主门店和同城授权门店集合。可以查看所有已授权门店服务单和顾客画像，确认服务、结束服务。只能在当前实际服务门店新增画像，默认只能修改自己创建的记录。不能修改目录、媒体、服务位、二维码、派单、结算、离位或清洁。

### 强制隔离规则

1. 所有业务表包含 `store_id`，总部数据与门店运营状态分层。
2. API、查询、写入、导出和媒体访问都必须校验门店上下文。
3. 跨店技师只能读取显式授权门店；写入只能绑定当前实际服务门店。
4. 店长不能跨店访问、转移或修改资源。
5. 总部跨店操作必须带目标门店并写审计。
6. 后端权限校验独立于前端菜单隐藏，拒绝越权请求。

## 5. 核心功能需求

### 5.1 总部目录管理

- 商品、服务项目、加项、分类、规格、价格、会员价、展示顺序和详情模块；
- 草稿、待发布、已发布、已停用状态；
- 发布到全部门店或指定门店；
- 总部强制下线；
- 历史订单保存名称、价格、规格、图片和详情快照；
- 已被历史单据引用的主数据只能停用，不得物理删除；
- 所有修改、发布、下线和调价均进入审计。

### 5.2 门店运营配置

- 门店、区域、房间、沙发、床位、服务位配置；
- 店长按真实现场新增、编辑、停用和排序；
- 二维码生成、下载、替换、作废和批量打印；
- 二维码必须绑定门店和服务位，作废后旧链接不可重新占用；
- 服务位支持启用、停用、维修备注和展示顺序。

### 5.3 服务位与服务单

服务单状态：`待确认 → 服务中 → 已结束 / 系统超时关闭`。

- 顾客提交选单后，店长或技师任一人确认即可进入服务中；
- 确认和结束操作幂等，重复请求返回当前结果；
- 店长或实际服务技师均可结束服务；
- 结束后项目、价格和数量不可直接编辑；
- 店长可发起受控更正，必须填写原因并保留前后值；
- 预计结束后超过 30 分钟仍未结束，DIY 自动关闭自身占用并记录审计；
- 已有智慧宝履约单时，DIY 不得覆盖智慧宝状态；
- DIY 只展示智慧宝状态，不提供开位、派钟、离位、清洁和释放动作。

### 5.4 会员与价格

- 外部会员系统为权威来源；
- DIY 保存外部身份映射、会员类型和同步时间；
- 会员登录后直接显示会员最低价，不领取优惠券；
- 非会员进入优惠券逻辑；
- 同步失败时使用有时效缓存并显示更新时间；
- 缓存过期后不自动授予会员价；
- 提交选单时冻结价格快照，价格计算可解释、可重放、可审计。

### 5.5 技师工作台

- 手机优先登录；
- 主门店和授权门店切换；
- 按当前门店查看待确认、服务中、已结束服务单；
- 确认服务、结束服务；
- 查看最小必要顾客画像；
- 新增服务偏好、禁忌、反馈和快记；
- 弱网重试、重复点击保护和操作结果提示。

### 5.6 顾客画像与隐私

画像字段包括偏好、禁忌、服务反馈、标签、技师快记和店长更正记录。

- 技师仅查看服务所需信息；
- 手机号默认脱敏；
- 身份证、支付信息等敏感字段不向技师开放；
- 店长查看本店业务所需信息；
- 总部按审计权限查看；
- 查看、导出、修改、作废全部留痕；
- 支持记录更正、作废原因和历史版本。

### 5.7 报表与导出

门店首期提供当日服务单、服务位利用率、项目销量、会员/非会员结构、评价概况和异常关闭。总部阶段提供跨店汇总、门店对比、商品/项目表现、技师服务量和异步导出。导出必须做权限校验、脱敏、有效期和下载审计，不混入财务结算数据。

## 6. 媒体资源需求

- 生产使用阿里云 OSS，开发使用本地存储或 MinIO；
- 支持主图、详情图、项目模块图、二维码；
- 上传、预览、替换、删除、拖拽排序、裁剪和压缩；
- 校验 MIME、扩展名、大小、像素和病毒扫描结果；
- OSS 路径按门店、业务对象和版本隔离；
- 使用预签名上传 URL 和受控 CDN URL；
- 删除采用软删除和引用检查；
- 删除仍被发布内容引用的资源必须先解除引用；
- 媒体操作支持失败重试、断点续传提示和审计。

## 7. 智慧宝集成需求

智慧宝仅提供数据 API，DIY 负责拉取，智慧宝不读取 DIY API。

阶段 0 必须取得 Base URL、认证方式、密钥轮换、服务位状态、房间/床位状态、技师派钟关系、开房/离位/清洁事件、履约单 ID、分页、游标、时区、频率限制和错误码。

DIY 内部统一适配器能力：`pull_positions`、`pull_assignments`、`pull_service_events`、`pull_fulfillment_orders`、`get_sync_health`。

要求定时拉取、增量游标、重试退避、本地快照、手动刷新、最后同步时间、数据新鲜度告警和 Mock 契约测试。真实联调、数据对账和故障演练完成前不得进入生产验收。

## 8. 验收标准

- 总部可完整编辑目录和媒体，店长只能上下架；
- 店长可独立维护本店技师、服务位和二维码；
- 跨店技师可查看授权门店，但只能在当前服务门店写入；
- 跨店访问、导出和敏感字段查看全部被审计；
- 服务确认/结束任一角色执行即可，重复请求幂等；
- 超时关闭不覆盖智慧宝履约单；
- 会员价格、非会员优惠券和价格快照正确；
- 媒体上传、替换、排序、引用保护和权限隔离有效；
- 旧 API 和现有顾客端在迁移期间保持兼容。
