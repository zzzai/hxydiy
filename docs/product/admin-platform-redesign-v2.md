# 荷小悦连锁门店管理后台 v2 产品规范

状态：设计基线，代码按本规范分阶段实施
版本：v2.0
日期：2026-10-21
适用范围：总部管理后台、店长端、技师端、门店工作台、评价与企微通知

## 0. 一句话定义

**店长端不是第二套后台，而是技师端加上门店管理权限。**

管理后台是连锁门店的运营操作系统：总部维护标准，店长经营本店，技师完成服务，系统保证每一笔订单、服务位、评价、权限和异常都有唯一事实、唯一责任人和可审计轨迹。

## 1. 产品原则

1. **角色叠加，不复制端**：店长 = 技师 + 门店管理权限；不另做店长专属 App。
2. **一个事实一个来源**：订单状态、服务位状态、评价状态只能由后端权威字段决定，前端不得自造状态。
3. **任务优先于菜单**：首页和导航围绕“今天要处理什么”，不是按数据库表铺页面。
4. **异常优先**：正常订单少打扰，异常、冲突、待跟进必须置顶。
5. **权限默认拒绝**：后端校验优先于前端隐藏；总部、店长、店员、技师各自最小权限。
6. **连锁可扩展**：所有数据带门店范围；总部跨店操作必须显式选择门店并审计。
7. **不伪造能力**：没有真实分配、确认、支付或物理资源释放时，不展示对应状态和按钮。
8. **可恢复**：每个写操作可重试、可追踪、有结果确认；失败不丢单。
9. **隐私最小化**：店长看经营所需，不默认暴露顾客敏感信息或技师私人记录。

## 2. 用户与 Jobs-to-be-Done

### 2.1 总部管理员

- 建立和维护连锁标准：门店、项目、商品、价格、内容、账号、授权。
- 跨店查看经营、处理异常、审计，不接管单店日常服务。
- JTBD：让所有门店按同一套标准运营，同时保留门店现场灵活性。

### 2.2 店长

- 本人也是技师，需要接单、服务、写服务记录。
- 作为门店负责人，需要看全店订单、服务位、加选、评价和异常。
- JTBD：既完成自己的服务，又保证门店今天顺滑运转。

### 2.3 技师

- 看本人任务，开始/结束服务，记录顾客服务参考。
- JTBD：快速确认今天做什么，准确完成并留下可靠记录。

### 2.4 店员

- 看现场订单、服务位和顾客到店情况，执行店长授权的现场动作。
- 不看经营分析、顾客隐私、评价跟进和目录配置。

## 4. 领域状态机

### 4.1 选单/订单状态

```text
draft
  → submitted（顾客提交）
  → confirmed（门店接单/系统自动接单）
  → in_service（开始服务；由占用状态驱动）
  → completed（服务结束）
  → evaluated（顾客评价；评价是附加事实，不改变已完成）
  → cancelled / expired（异常终止）
```

原则：

- `submitted` 是“已提交待接单”，不是“待店长逐单确认”的默认人工队列。
- 店长、技师或系统可接单；具体策略按门店配置，但状态只有一个。
- 订单是否已评价由评价事实派生，不伪造订单状态。
- 取消必须记录操作者、原因、时间；已服务完成不可直接回退。

### 4.2 服务位占用状态

```text
available
  → held（扫码/选购中）
  → waiting_service（已提交/已接单，待服务）
  → in_service
  → post_service_present（服务结束，待离位/清洁确认）
  → cleaning
  → released
```

- 物理开位、离位、清洁由智慧宝负责；DIY 只读展示，不伪造。
- 同一服务位同父房间只允许一个活动选单。
- 服务位状态必须与订单状态联动，但不能由前端单独修改。

### 4.3 加选状态

```text
awaiting_staff_confirmation → approved / rejected
```

- 店长或授权店员处理；
- 拒绝必须填原因；
- 处理结果写审计并回写订单快照；
- 不自动通过，避免价格和库存风险。

### 4.4 评价与跟进

```text
评价：submitted（一单一评）
跟进：none → pending_follow_up → followed_up / no_action_needed
```

- 1–2 星自动进入待跟进；
- 店长可写跟进备注、标记已跟进；
- 不可修改评分、标签和顾客原文；
- 跟进状态进入审计和企微通知。

### 4.5 员工/技师状态

```text
Staff: active / disabled / resigned
Technician: available / busy / off / resigned
员工授权: active / revoked
```

- 店长必须有 Technician 档案；
- 店长保留 technician_id，同时拥有 store_manager 授权；
- 离职、撤销授权立即失效令牌；
- 历史服务、订单和审计不删除。

## 5. 信息架构

### 5.1 店长/技师移动端

```text
底部导航
今日服务 | 服务记录 | 我的 | 门店（仅店长）

门店
├── 总览（今日订单/服务中/待结账/需处理）
├── 待处理（异常、加选、冲突）
├── 订单（今天/全部、状态筛选、座位筛选）
├── 座位（沙发/房间，按技师端布局）
└── 评价（今日/近7天/全部、低分优先、跟进）
```

规则：

- 店长默认落在「今日服务」，可切「门店」；
- 没有门店任务的技师不显示「门店」；
- 店长自己的服务任务与全店订单分开，不混排；
- 门店页只处理增量职责，不重复技师操作。

### 5.2 桌面管理后台

```text
工作台（今日异常/待办）
运营：今日运营、订单、服务位、到店选单
顾客：评价与反馈、用户、标签、分群
服务与商品：项目、加项、商品、页面配置
人员与权限：技师、员工账号、授权
门店与资源：门店、房间/服务位、二维码
经营：分析、结算记录、审计
系统：自动化、集成、设置
```

规则：

- 一级导航按运营任务分组，不按数据库表；
- 默认页是工作台，不是某个列表；
- 页面标题必须一条一句话说明当前任务；
- 跨店/总部视图明确门店上下文。

### 5.3 订单详情统一组件

订单详情是全端唯一事实页，包含：

```text
状态 + 服务位 + 订单号
顾客：昵称/会员状态（最小必要）
项目：名称、数量、会员价/门店价、实际计价
金额：顾客应付/已确认金额
时间线：提交、接单、开始、结束、评价
操作：按状态和权限显示；禁止动作不显示
来源：到店/扫码/门店平板
```

## 6. 关键流程

### 6.1 到店下单

1. 顾客扫码/门店平板创建选单；
2. 选择项目、偏好、加选、服务位；
3. 服务端计算并冻结价格；
4. 提交后生成订单事件；
5. 系统按门店策略自动接单或进入待接单；
6. 店长/技师在今日服务或门店订单看到；
7. 企微卡片通知店长（目标可配置，默认本店店长）；
8. 点击卡片自动登录并打开该订单详情。

### 6.2 店长作为技师服务

1. 店长登录后先看到本人今日服务；
2. 开始服务、结束服务按技师流程；
3. 写本人服务参考；
4. 需要门店处理时切到「门店」，不丢失本人任务上下文。

### 6.3 加选

1. 顾客服务中追加项目；
2. 生成加选请求；
3. 店长在「待处理」看到，显示原订单、加选项目、价格；
4. 确认或拒绝；拒绝必须原因；
5. 结果回写订单并通知顾客。

### 6.4 评价与跟进

1. 服务完成后顾客评价；
2. 评价写入本店评价列表；
3. 低分自动标待跟进；
4. 店长查看订单上下文、评分、标签、原文；
5. 标记已跟进/无需处理并写备注；
6. 企微通知店长新评价；卡片深链到评价详情。

### 6.5 异常

异常类型：

- 服务位冲突
- 订单状态冲突
- 顾客长时间未到
- 服务超时
- 加选待处理超时
- 低分待跟进
- 企微通知失败

要求：异常有负责人、创建时间、处理动作、关闭原因；工作台按严重度和时长排序。

## 7. 页面规范

### 7.1 工作台/总览

- 顶部：门店、今日日期、当前班次、刷新；
- 核心指标：今日订单、服务中、待结账、需处理；
- 待办优先列表：只显示需要动作的异常，不重复全部订单；
- 空态明确“今天没有需要处理的事项”。

### 7.2 订单列表

- 默认今天；
- 筛选：待处理/全部/已完成/已取消；按状态、服务位、来源、关键词；
- 每单：服务位、项目摘要、金额、状态、时间、下次动作；
- 不让用户通过翻页寻找异常；异常有独立入口。

### 7.3 座位

- 与技师端一致：沙发/房间分组；
- 床位按房间号展示，不显示 A/B 床；
- 状态色：空闲/待服务/服务中/已结束/异常；
- 点击看当前订单和订单详情；
- 店长不做“逐单分配”；安排动作仅在现场需要时出现。

### 7.4 评价

- 列表：评分、标签、摘要、订单、时间、跟进状态；
- 默认低分优先；
- 详情：订单上下文、评分、标签、原文、跟进记录；
- 操作：标记已跟进/无需处理 + 备注；不可编辑原文。

### 7.5 目录/人员/门店

- 仅展示与店长职责相关的操作；
- 总部专属操作不出现；
- 所有编辑有保存状态、校验、撤销、审计。

## 8. 交互与质量规范

- 加载：骨架/局部 loading，不整页白屏；
- 空态：说明为什么空、下一步做什么；
- 错误：用户可理解中文 + 重试；内部错误只进日志；
- 弱网：写操作幂等、结果确认、防重复提交；
- 权限：403 显示明确原因和可返回路径；不静默空白；
- 可访问性：键盘、焦点、对比度、44px 触控区域；
- 移动端：底部安全区、单手操作、不可横向溢出；
- 性能：首屏关键数据优先，列表分页/懒加载；
- 埋点：关键路径成功率、异常处理时长、通知点击率。

## 9. 数据与接口

- 订单/评价/服务位查询必须带 store_id；
- 店长接口按 store scope 校验；
- 技师接口按本人 technician_id 校验；
- 店长绑定 technician_id 后同时通过两类校验；
- 列表接口返回权威状态、更新时间、当前动作建议；
- 详情接口与列表使用同一 view model，避免两端字段漂移；
- 企微通知记录目标、消息类型、结果、去重键；
- 所有写操作审计 actor、门店、前后值、幂等键。

## 10. 迁移与兼容

1. 先改身份模型：允许店长绑定技师；
2. 补张震技师档案绑定；
3. 店长端路由保留旧路径兼容，逐步切到技师壳；
4. 桌面后台保留旧菜单别名，避免书签失效；
5. 旧订单/评价数据不重写；
6. 每次迁移可回滚，先备份、预览、审计；
7. 生产发布前必须有真实恢复演练。

## 12. 非目标

- 不做真实支付/退款执行；
- 不做智慧宝物理开位、离位、清洁动作；
- 不做自动派单/排班算法；
- 不做总部财务合并报表；
- 不做顾客端功能扩张；
- 不用前端文案替代后端状态。
