## 当前门店工作与范围

荷小悦连锁业务本轮首先保证总部能维护服务项目、价格与顾客可选内容，门店能按现有权限使用项目。店长与技师共用移动工作台，权限不同；本轮不是另外造一套店长桌面入口。项目资料与目录版本仍是现有两类保存行为，不把未实现的整项目草稿宣称为已实现。

本轮交付：服务项目编辑、真实保存、选项草稿创建与发布、错误恢复；操作记录、顾客分群、规则配置不再让业务人员阅读或编辑 JSON。暂不扩展支付、退款、结算、自动发券、营销消息、员工权限、会员权益或数据库结构。

## 操作流程及生效规则

1. 在服务项目列表按门店查看项目，以名称、分类、时长、价格及状态识别项目。
2. 项目资料按“项目内容／项目价格／展示设置”组织；金额按元填写，接口仍使用分。保存项目资料会立即更新资料；只读查看不写库。
3. 已发布的顾客可选内容只读。总部点击“创建编辑草稿”，服务端锁定项目并复制当前发布目录；有草稿则复用。读回新草稿的组和选择 ID 后才启用编辑、删除、新增。
4. 分组和选择项分别保存到草稿。未发布时顾客继续使用原目录；不得修改原已发布图、价格快照或顾客历史选单。
5. “检查与发布”读取真实校验和价格试算；有未保存项目资料时不能发布。示例组合明确是必选项最少组合，不冒充顾客全部加购金额。
6. 发布成功显示版本已发布；返回可选内容重新取当前版本。需要再修改则重新创建草稿，不沿用已发布的旧 ID 当成草稿。
7. 关掉未保存的表单需提示丢弃；请求失败保留填写内容。422 提示具体业务字段，403 提示权限，409 提示核对版本，超时明确结果未确认，不伪称保存成功。

## JSON 字段的业务呈现

- 操作记录：动作、对象显示中文；摘要只显示已知安全字段；未识别历史详情保留原记录，用编号供追溯，不渲染原 JSON。
- 顾客分群：现有标签多选（任一标签满足）、已有会员标记开关、已保存人数（非实时）；会员标记不等同有效年卡权益。旧条件仍保留，未知条件提示待核验，不擅自重写。
- 自动化规则：触发条件与动作显示业务名称；当前未核实可用执行引擎，因此本轮只允许已有标签的停用规则配置。不开启规则、不执行动作、不发消息、不发券，不把“保存配置”称作“已自动执行”。
- 页面内容：沿用 v2 的表单化编辑、版本和门店隔离；本轮真实接口预览纳入同一入口。

## 权限和验收标准

目录主数据写入仍限总部管理员；店长、其他门店管理员、普通员工不能借新入口提权。新接口不新增表或迁移。
