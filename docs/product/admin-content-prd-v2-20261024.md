# 荷小悦连锁后台：内容维护 PRD v2

日期：2026-10-24。范围：A1 服务项目与 A6 顾客页面内容的可操作预览。此文补充上一版，不覆盖已有记录；不是生产交付声明。

## 当前最需要解决的业务

总部能准确维护各门店服务标准、项目价格与顾客文案；店长处理本店选单、分配和履约，技师处理本人服务。店长与技师共用移动工作台，权限不同，不另建一套桌面店长端。本轮不扩大财务、支付、退款或营销自动化。

内容维护必须完成“选对门店 → 找到内容 → 看懂字段 → 编辑 → 核对 → 保存/生效 → 再次读取”的闭环。失败时能知道下一步，不能以空列表或默认值掩盖读取失败。不得要求门店人员编辑 JSON。

## 核实后的事实与限制

- 项目内容和价格保持总部维护；店长仍只能执行原有项目启停范围。所有服务端权限、门店隔离、元/分计价和目录发布检查不变。
- 项目列表经过数据提供器缓存，单纯 reload 可能不重新请求。本轮显式失效项目缓存再刷新；不改全局缓存策略。
- 页面配置存储为一条当前记录，发布时另生成历史版本。停用后顾客读取默认内容；不存在“编辑新草稿同时保留线上旧内容”的双版本能力。
- 顾客首页目前使用推荐位角标、标题及到店礼提示。推荐图、价格和跳转仍来自原项目，精油 SPA 标题沿用项目名。页面标题、副标题、茶饮与品牌故事没有接入当前首页展示，不能在配置端声称已展示。
- 页面配置 GET 在缺记录时会创建默认记录。因此本轮预览使用合成 adapter，不对生产执行这些读取或写入接口。真正只读 GET 的后端修复另列，不能用本轮 UI 掩盖。

## 功能定义与验收

### A1 服务项目维护

角色：现有总部管理员维护项目；店长按现有权限启停。入口：服务项目列表。

1. 项目内容、价格、展示设置分组；项目资料、顾客可选内容、检查与发布分栏。编辑器标明项目名。
2. 三档价以元显示/输入、按契约以整数分提交。关联项目用中文及人民币金额显示，不输出对象或枚举。
3. 列表读取失败显示错误和重试，不误报“没有项目”；失败期间不诱导新建。刷新确实重新读取服务器。
4. 保存失败保留输入。无权限、校验失败、网络中断、超时、状态冲突使用不同提示；不渲染后端 JSON、输入值、堆栈或数据库信息。
5. 未保存关闭须确认；发布检查未通过不允许发布。重复点击保护、切换项目后的旧请求防护沿用现有实现。

验收：编辑/保存/刷新后重新打开；列表失败重试；403/422/超时提示；可选内容中文价格；元分准确；旧内容保留；店长不能编辑价格。

### A6 顾客页面内容

角色：按既有 manage_catalog_master 能力，不新增角色或权限。总部明确选择门店；绑定门店的账号保持原范围。

入口与结束：顾客页面内容 → 选择门店 → 首页文案/茶饮与品牌素材/生效设置 → 文案预览 → 保存 → 成功提示与状态更新。

- 首页文案：推荐角标、推荐标题逐行编辑，可添加、移除、上移；操作按推荐位顺序生效，不改变项目图、价格或跳转。到店礼标题及说明仅改文案，不发券。
- 茶饮素材：名称、简述、说明、配图结构化维护；品牌故事：标题、正文、配图。明确这两组素材尚未在当前顾客首页展示。
- 旧配置中未展示的扩展字段跟随各行保留；删除/排序不把另一行扩展字段拼到当前行。无法兼容的旧数据禁止保存并提示处理，不静默清空。
- 配图移除仅移除表单引用，保存后才影响配置，不删除原图片文件。新上传沿用现有上传接口和门店范围。
- 生效开关为“使用本店页面内容”。开启时按钮为“保存并生效”；关闭时为“保存配置（使用默认内容）”。关闭不能表述为保留线上旧版的草稿。
- 侧栏仅预览文字排布，标明未保存状态；不模拟价格、领取资格、实际项目推荐或未接入板块。
- 门店未选择不发配置请求。读取结果与所选门店不一致时阻断编辑；请求序号防止过期读取覆盖新门店。
- 切换门店或重新加载前，有未保存修改需确认丢弃；取消则仍在原门店。保存/恢复版本进行中不允许切换门店或重复提交。
- 版本列表失败可重试，不能假装没有历史。恢复历史内容要明确立即生效、替换本店当前配置及丢弃未保存修改，成功后重新读取。无自动重试写操作。

验收：结构化往返不丢旧字段；编辑/增删/排序；失败保留输入；切店确认；门店错配阻断；网络/校验错误；版本读取失败重试；停用说明和 payload 一致；窄屏可操作。

## 视觉与信息规范

纯白内容面、浅绿辅助预览、深绿主操作，暖金仅用于待保存等少量提醒。复用现有品牌变量与字体。页面标题 24px、区块标题 16px、正文 14px；稳定双列字段、桌面文案侧栏、窄屏单列。页面只保留一个明确保存入口，底部固定操作区不遮挡表单。

所有正常、空、加载、失败、无权限、状态冲突、未保存状态必须提供业务语言和下一步操作。不能依赖一条笼统“请求失败”吐司；不能把代码字段、JSON 或机器错误当作运营说明。

## 未纳入本轮实现的事项

- 审计日志的详情 JSON、顾客分群条件 JSON、自动化动作 JSON 仍需分别按业务含义整改，不宣称全站已经消除。分群/自动化与营销权限及发送行为有关，先补独立 PRD 和能力清单，不能仅换成表单后默认启用。
- 项目多窗口并发版本保护、真实上传/删除、目录复制等发布前仍需隔离 API 验收。
- 页面配置 GET 的创建副作用、独立草稿保留线上旧版和未接入素材的顾客端展示属于后续跨端能力，不在本轮修改后端或数据库。
- A2 继续围绕选单接单、无座提交、门店分配、履约记录和异常处理结果；不把“知悉”当“已解决”，不做支付退款闭环。
