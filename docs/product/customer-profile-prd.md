# 荷小悦 DIY 顾客端“我的”生产级升级 PRD

## 0. 文档信息

- 版本：v0.9；日期：2026-09-05
- 状态：产品方向已确认，待工程与运营评审
- 范围：顾客端 H5、顾客身份及本人记录 API
- 产品原则：帮助顾客看懂权益、找到待办、查清记录、继续选购

## 1. 执行摘要

将“我的”从并列数据列表升级为顾客任务中心：手机号账号仅保留最近登录设备；会员可看有效期和基于已完成服务真实价格快照计算的累计节省；顾客可在统一到店记录中发现待评价服务、打开本人详情、评价并再次选购。本项目不改变线下结算和物理服务位职责。

## 2. 问题与证据

### 已确认问题

1. JWT 只验证签名与有效期，同一手机号可在多个设备同时有效。
2. “服务记录/到店记录”是内部模型拆分，不符合顾客心智。
3. 已完成未评价服务没有待办入口。
4. 到店记录不可点击，无法核对项目、金额和状态。
5. 后端保存了 `member_expire_at`，登录快照和会员卡未展示。
6. 会员卡只有权益口号，没有用真实服务证明会员价值。

证据来自 2026-09-05 用户现场反馈及当前源码/API 核对。🔵 **待采集**：页面访问量、记录点击率、服务完成到评价的转化率、跨设备登录发生率暂无可信生产基线。

## 3. 用户与核心任务

- 普通登录顾客：查到店历史、处理待评价、再次选购。
- 会员顾客：确认会员是否有效、何时到期、实际省了多少。
- 多设备登录顾客：理解旧设备为何退出且不丢失匿名选购。

核心任务：服务结束后完成评价；回看项目和金额；确认会员权益；在历史记录后继续选购。

## 4. 产品目标与指标

### 目标

1. 首屏先展示身份、会员价值和待办，不暴露后台数据分类。
2. 打通服务完成、详情、评价和再次选购闭环。
3. 单设备登录由服务端强制，前端只负责提示与清理身份。
4. 会员节省可解释、可追溯，不混入优惠券或当前菜单价格。

### 指标

- 主指标：待评价点击到评价提交成功率。
- 次指标：记录详情打开率、再次选购点击率、会员权益查看率。
- 安全护栏：新登录后旧令牌撤销成功率 100%。
- 数据护栏：累计会员节省与历史快照抽样核对一致率 100%。
- 稳定性护栏：登录失败率、“我的”接口错误率和白屏率不得劣于发布前基线。
- 🔵 **待确认**：上线后先观察14天，再设增长目标，禁止编造提升比例。

## 5. 信息架构

“我的”首页依次为：

1. 账户区：昵称/身份、脱敏手机号、退出。
2. 会员权益卡：会员状态、有效期、累计会员省、已完成服务次数、查看权益。
3. 待办区：仅有未评价服务时显示“待评价 N”。
4. 到店记录：统一承载历史，提供“全部/待评价/服务中/已完成”。
5. 非会员可有克制的“到店了解会员”；发券暂停期间不出现领券内容。

到店记录整卡可点击，展示状态、时间、项目摘要、总数量、当次金额、评价和再次选购。详情展示状态时间线、门店/服务位（有可靠快照时）、项目与追加项、偏好、门店价、会员价、采用价格带、评价状态和线下结算说明。返回保留筛选和滚动位置。

## 6. 核心业务规则

### 6.1 单设备登录

1. 同一手机号仅允许最近一次顾客登录有效。
2. 新设备验证码登录成功时，服务端原子撤销旧会话。
3. 旧设备访问任何顾客登录接口时返回 HTTP 401：
   - `code=SESSION_REPLACED`
   - `message=账号已在另一台设备登录，请重新登录`
4. 前端清除手机号身份，但不得清除匿名浏览器身份、未提交选择、服务位参数和服务端记录。
5. 页面前台停留时每60秒刷新身份；任一业务请求也负责发现失效。本期不引入 WebSocket。
6. 顾客主动退出不删除业务数据。

### 6.2 会员生命周期

| 状态 | 条件 | 展示 |
|---|---|---|
| 有效 | 剩余超过30天 | 年度会员、有效期至日期、当前享会员价 |
| 临期 | 剩余1–30天 | 还有N天到期、到店续费 |
| 已到期 | 到期日不晚于当前时间 | 会员权益已到期、到店续费 |
| 待同步 | `is_member=true` 且无到期日 | 状态以门店记录为准 |
| 非会员 | `is_member=false` | 普通顾客、到店了解会员 |

顾客端不在线支付，不出现“立即购买/在线续费”。

### 6.3 会员本人使用：可信设备与动态会员码

#### 保证边界

- 会员权益原则上仅限办理人本人使用；短信验证码只证明能接收短信，不能单独证明本人。
- 采用“唯一登录会话＋唯一可信设备＋30秒动态会员码＋员工现场核验＋风险控制”。该组合能阻止报手机号、转发静态码、共享验证码和多设备并行，但无法绝对阻止会员本人把已解锁手机实时交给他人，异常情况仍需门店核验。

#### 三端职责

| 端 | 职责 | 禁止事项 |
|---|---|---|
| 顾客端 | 展示可信设备状态，生成动态码、倒计时和换机申请 | 自行声明会员、改价、在码中暴露个人资料 |
| 技师端 | 技师或店长登录后扫码、查看最小核验结果、绑定本店当前选单 | 手输手机号套会员价、跨店核验、查看无关消费记录 |
| 电脑管理后台 | 策略配置、授权、设备换绑审批、异常处置和审计 | 承担日常扫码、绕过动态码启用会员价 |
| 后端 | 签发/验证/消费动态码，校验会员、会话、设备、角色、门店和选单，重算并审计 | 信任前端会员状态或仅凭手机号返回会员价 |

日常扫码入口放在技师端移动页面。现有技师账号可以扫码；店长账号若进入技师端扫码，后端必须赋予独立的 `membership_verify` 门店权限，不能假装成技师，也不能因此获得技师确认/结束服务权限。

#### 可信设备

- 可信设备是会员手机浏览器的一条服务端绑定记录，不是门店采购硬件。
- 使用服务端随机高熵凭证；客户端采用 `Secure + HttpOnly + SameSite` Cookie，服务端只保存哈希。
- 禁止采集 IMEI、通讯录、广告ID或隐蔽设备指纹。
- 每会员同时仅一台可信设备；新设备短信登录后处于“会员权益待验证”，不能生成会员码或获得会员价。
- 新设备须经原设备批准或管理后台受控换绑。换绑后旧设备、旧会话和全部未消费会员码立即失效。
- 清除浏览器数据、无痕模式或更换浏览器视为新设备，顾客端必须提前提示。
- 🔵 **合规评审项**：原设备不可用时的本人核验材料和留存周期。默认不采集人脸，不保存身份证照片或号码，只记录核验结果、员工、门店、时间和原因。

#### 动态会员码

- 仅在会员有效、当前唯一会话有效且当前设备可信时签发。
- 二维码只含不透明随机令牌，不含手机号、姓名、会员ID、到期日或价格。
- 有效期30秒；同会员同时仅一个有效码，新码生成即撤销旧码。
- 状态机：`issued → scanned_pending → consumed`，并支持 `expired/revoked/rejected`。
- 扫码后令牌短暂锁定给当前员工、门店和待绑定选单；未确认则超时。
- 绑定成功后一次性消费，不能再次扫码或绑定第二笔选单。

#### 技师端扫码流程

1. 技师或店长在技师端进入“会员核验”并授权摄像头。
2. 扫码后由后端校验会员有效期、唯一会话、可信设备、码状态、员工角色和门店范围；客户端不得离线判定。
3. 技师端仅显示脱敏姓名、脱敏手机号、会员状态、到期日和核验结果。
4. 操作者选择本店当前待确认服务位/选单并确认绑定。
5. 后端再次校验并在一个事务中完成“消费码＋绑定顾客＋重算会员价＋写审计”；任一步失败均不得留下半完成状态。
6. 顾客端和技师端刷新服务端价格结果。

扫码不等于确认/结束服务，也不触发物理资源状态；操作者不能手工改金额。

#### 风险、旁路与硬件

- 频繁换绑、同日不合理跨店、同会员并发多笔服务、同设备频繁切换会员、动态码重放或换绑后立即高频使用时，返回“需要店长核验”，不得自动应用会员价。
- 风险信号只用于权益安全，不转为顾客画像或营销标签。人工放行要求店长权限、原因、关联选单和幂等键，并审计前后状态。
- 禁止手机号查询直接启用会员价、自由勾选会员或前端改价等旁路。
- 首期复用技师/店长现有手机摄像头，不要求扫码枪、身份证阅读器或人脸设备。摄像头或网络不可用时不得离线放行，应换用另一台已授权手机。

### 6.4 累计会员节省

```text
单次会员节省 = max(当次门店价快照 - 当次会员价快照, 0)
累计会员节省 = 所有符合条件服务的单次会员节省之和
```

计入必须满足：服务存在权威结束时间、记录属于当前顾客、金额来自提交或确认时的服务端价格快照、记录非草稿/取消/过期。

明确排除：当前菜单价倒推、优惠券、人工减免、储值余额、未完成服务、缺失或异常金额。存在完成记录时显示“累计会员省 ¥X/已完成 N 次服务”；没有时显示“完成首次服务后可查看”，不显示误导性的 `¥0`。该金额不代表余额或可提现资产。

### 6.5 待评价

- 待评价 = 存在权威服务结束时间且没有评价记录。
- 首页只在数量大于0时显示待办；点击进入待评价筛选。
- 提交成功后立即移出待办并显示已评价。
- 重复提交返回既有评价，不创建第二条。
- 登录顾客仅可评价本人服务；原匿名设备仍可凭合法选单凭证评价。

### 6.6 统一到店记录

- 合并“服务记录/到店记录”为“到店记录”。
- 服务中：`waiting_service` 或 `in_service`。
- 已完成：存在服务结束时间；运营状态 `post_service_present/cleaning/released` 不改变顾客侧已完成语义。
- 待评价是已完成记录的子集；取消和过期保留在“全部”。
- 最近优先，首版最多50条，未来改游标分页。

## 7. 用户故事与验收

### Story 1：单设备账号

作为手机号顾客，我希望账号只在最近设备有效。

- [ ] 第二台设备登录后，第一台访问本人接口返回 `SESSION_REPLACED`。
- [ ] 第二台正常访问；第一台最长60秒或下一次请求时看到原因。
- [ ] 清理手机号身份不影响匿名选购和服务位。

### Story 2：会员价值

作为会员，我希望看到有效期和真实累计节省。

- [ ] 有效、临期、过期、缺失到期日均有文案。
- [ ] 仅已完成服务历史快照计入；优惠券和未完成记录不计入。
- [ ] 无完成记录不显示 `¥0`。

### Story 2A：会员本人动态核验

- [ ] 非可信设备短信登录后不能生成会员码或获得会员价。
- [ ] 动态码30秒过期、同会员仅一个有效码、消费后不可重放。
- [ ] 技师或店长只能通过技师端在授权门店扫码并绑定本店可操作选单。
- [ ] 绑定原子完成会员、码、门店、选单校验、价格重算和审计。
- [ ] 动态码不含可直接读取的个人资料。
- [ ] 手机号查询、自由勾选会员和前端改价不能绕过核验。
- [ ] 换绑后旧设备、旧会话和旧码全部失效；人工放行仅店长可执行。

### Story 3：待评价

作为已完成服务的顾客，我希望直接看到并完成待评价任务。

- [ ] 待评价数量准确，0时不显示大块空模块。
- [ ] 评价成功后数量和列表即时更新。
- [ ] 网络失败保留原记录并可重试，不伪装为空。

### Story 4：到店详情

作为顾客，我希望点击整张记录核对项目和金额。

- [ ] 整卡支持触摸、Enter和Space，目标不小于44px。
- [ ] 仅本人可访问；他人记录统一404。
- [ ] 展示项目、数量、时间、状态与历史价格快照。
- [ ] 返回保留筛选状态。

### Story 5：再次选购

- [ ] 从历史记录返回当前门店/服务位项目列表。
- [ ] 不自动复制历史项目，避免误提交。
- [ ] 不修改技师端、智慧宝或物理资源状态。

## 8. API 与数据契约

### 登录快照

`POST /auth/h5/login` 与 `GET /auth/h5/me` 增加 `member_expire_at: datetime|null`。JWT 增加可校验的登录代次或等价会话标识；存储方案可由技术设计确定，但必须支持原子撤销和审计。

### 我的到店记录

`GET /selection-sessions/mine` 每条增加：`occupancy_status`、`service_completed_at`、`can_evaluate`、`evaluated`，保留 `store_total_cents`、`member_total_cents`、`pricing_snapshot`。履约与评价状态由后端聚合，前端不得逐条猜测。

### 本人详情与评价

- 增加本人详情接口，以 Bearer token 校验 `customer_id`。
- 评价兼容本人 Bearer token 与原匿名选单凭证。
- 任一凭证不得跨顾客或跨选单访问。

### 动态会员核验

- 顾客端：动态码签发/刷新/撤销及可信设备状态查询。
- 技师端：扫码预检、选单绑定；店长与技师使用同一移动入口但服务端按角色授权。
- 管理后台：可信设备撤销/换绑审批、风险策略、异常处置和审计，不提供日常扫码。
- 动态码消费与会员选单绑定必须使用幂等键和数据库事务。

## 9. 埋点与隐私

建议事件：`profile_view`、`profile_pending_feedback_impression/click`、`profile_record_filter/click/detail_view/reselect_click`、`membership_card_impression/detail_click`、`session_replaced_logout`、`member_code_issue/expire`、`member_code_scan_result`、`member_code_bind_result`、`trusted_device_change_result`。

只允许匿名分析ID、客户端会话ID、门店ID、记录状态、会员状态和到期天数分桶。禁止记录完整手机号、验证码、JWT、评价原文或其他顾客敏感数据。

## 10. 非功能要求

- 移动优先，360–520px 不遮挡；触控目标不小于44px。
- 状态变化必须有文字，不只靠颜色；适配字体放大和换行。
- 模块独立容错，券或单类记录失败不得导致整个页面白屏。
- 本地缓存不得替代服务端会员、价格、评价或履约事实。
- 断网保留已显示内容并标记刷新失败，不冒充最新数据。

## 11. 范围外

- 在线购买、续费、支付、退款、核销。
- 新发券策略；继续执行暂停发券。
- 技师派单、接单、确认、结束、离位、清洁和物理释放。
- 智慧宝状态写入；管理端/技师端页面改版。
- 会员等级、积分、成长值、储值改造及基于消费能力的营销。
- 人脸识别、身份证阅读器、设备指纹和保存证件照片/号码。

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 历史记录缺结束时间 | 只统计权威结束时间，不由前端补猜 |
| 历史价格快照不完整 | 缺失记录不计入；上线前生产只读抽样 |
| 共享平板因单设备规则掉线 | 仅约束手机号身份，匿名到店选购保持可用 |
| 身份与到期日不一致 | 降级显示“以门店记录为准”并记录数据质量问题 |
| 两套历史直接拼接重复 | 以选单会话为主记录，订单仅作必要补充 |
| 登录评价越权 | 后端强校验本人关系，跨用户返回404 |
| 动态码截图或实时转发 | 30秒、单码唯一、扫码锁定、一次消费和异常频率控制 |
| 技师端扫码扩大权限 | 独立 `membership_verify` 权限，不附带服务动作权限 |
| 换机恢复采集过多信息 | 合规评审与最小化核验，默认不保存证件影像/号码 |
| 网络或摄像头不可用 | 不离线放行，换用另一台已授权手机 |

## 13. 发布与回滚

发布前必须：生产备份及恢复验证；迁移验证；旧令牌撤销、可信设备、动态码过期/撤销/重放、跨店/越权、原子绑定、本人详情和评价幂等合同测试；顾客端与技师端覆盖会员/非会员、生命周期、摄像头拒绝、弱网与空状态；三端相关测试、构建和 `git diff --check`；服务器 release、Manifest、容器、首页、健康接口与静态资源核验。

新增数据库字段应有安全默认值。旧用户不因部署立即退出，下一次手机号登录开始单设备约束。前端对新增可空字段降级。严重问题回切上一 release，新增兼容字段可保留。自动化与公网探针不等于门店验收。
