## 1. 目标与非目标

技师在服务结束后，用不超过 30 秒记录顾客主动提及、且会影响下一次服务的身体相关情况。记录用于本店下次服务前的再确认与本次服务连续性，不能变成疾病档案、诊疗结论、营销分层或差别定价依据。

本期不记录诊断、检验结果、药品名称、精确病历、收入或疗效；不做自动识别、语音采集、跨店共享、长期画像投影或算法评分。

## 2. 用户与核心场景

作为当前服务的技师，我在结束服务后知道顾客提到过某个具体部位曾受伤、近期不适或处于恢复中，希望快速标出部位并写清本次如何处理；下一次服务前，我只看到“需再确认”的脱敏服务提醒。

该流程只对当前登录技师、本店、当前或刚完成的本人服务开放。顾客为匿名身份时，记录仅归属当前匿名顾客主体；同一浏览器身份不是自然人证明，后续只有顾客可信登录并主动确认时才能按既有身份合并规则处理。

## 3. 交互与信息架构

入口为服务结束后的“更多服务记忆”中的“记录身体相关情况”。打开全屏移动抽屉，顶部依次展示：

1. 选部位：正面与背面人体图；点位可多选，已选点以绿色勾选态和底部清单呈现。
2. 选情况：针对当前编辑点位选择顾客自述的情况。
3. 当前状态：选择当前仍有不适、偶尔不适、目前无明显不适或需下次确认。
4. 本次处理：选择本次避开、减轻力度、确认后正常进行或本次观察并下次确认。

底部清单按选择顺序显示“部位 · 顾客自述情况”，可进入编辑或删除；最多三条。点位可取消。完成后返回服务参考主页，仍需由技师选择顾客确认状态才能保存。

所有触控目标不小于 44px；390×844 微信浏览器中底部主按钮不被导航遮挡；无点位、无网络、保存失败、编辑与删除均有明确文字状态。

## 4. 文案与安全边界

页面固定提示：`只记顾客自述，不作诊断`。文案使用“顾客提及曾受伤”“顾客提及术后恢复中”“顾客提及近期不适”“顾客提及长期不适”“顾客提及皮肤敏感”“下次请确认”，不把“肩周炎、滑膜炎、结节”等疾病或诊断词作为结构化标签或默认展示。

如顾客使用诊断式说法，技师转写为不带诊断的服务影响，例如“右肩 · 顾客提及长期不适”；不得在自由文本中重复记录疾病名、药品名或治疗结论。身体记录默认不进入当前画像投影、管理端列表、运营标签、搜索索引、算法特征或营销。

## 5. 数据契约

新增写入版本 `schema_version=5`、`taxonomy_version=service_reference_v4`。v1–v4 继续只读兼容，既有 v4 不改写。

`customer_reported.body_service_notes` 最多三条，每条为：

```json
{
  "region": "shoulder",
  "side": "right",
  "context": "long_term_discomfort_mentioned",
  "current_state": "occasional_discomfort",
  "session_handling": "lighter",
  "reconfirm_next_visit": true
}
```

`region` 为稳定部位编码；`side` 仅允许 `left`、`right`、`center`，由点位决定。`context`、`current_state` 与 `session_handling` 均为后端白名单编码，拒绝未知编码、重复点位、跨服务写入及超过三条的请求。中文只由字典映射展示。

## 6. 权限、隐私与历史

- 后端继续校验当前技师、服务归属、门店范围、完成状态、幂等键及顾客确认字段。
- 原始服务记录保持追加式；误填通过新更正记录或删除本次未保存草稿处理，不覆盖历史事实。
- “查看上次服务参考”仅显示同店、本人可见、已确认且未过期的安全摘要；身体记录只显示“身体情况：服务前再确认”，不显示病情、原话或完整历史。
- 管理端如后续获得专页，只能按门店、授权、时间线受控查看原始记录；不在客户列表暴露。
- 顾客拒绝确认或未确认时，记录仅是本次服务事实，不投影为长期偏好。

## 7. 验收标准

- 正反面所有可点击点位与 `region + side` 稳定映射；左、右、中央部位不混淆。
- 选择两个点位后，底部显示两个可编辑条目；删除或取消立即同步人体选中态。
- 每个条目必须完成“情况、当前状态、本次处理”后才能进入下一步；最多三条。
- 提交 payload 为 v5，后端拒绝未知字段、诊断词自由文本、重复部位、越权、跨店和超限。
- v1–v4 历史仍能读取；v5 历史能按安全摘要降级展示，不泄露原话或敏感情况。
- 后端合同测试、技师端单元测试、TypeScript、生产构建和 390×844 真机/微信浏览器验收通过。
- 生产发布前完成数据库迁移升级与降级演练、备份恢复、同店/跨店权限、幂等重试和线上入口检查。自动化与线上健康检查不替代门店现场验收。

## 8. 发布与衡量

先单店灰度。上线后只采集不含敏感正文的过程指标：打开率、完成率、保存失败率、填写时长分桶、下次服务前再确认点击率。14 天建立基线后再决定是否优化点位与字典；不宣称医疗或经营效果。
