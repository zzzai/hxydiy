# 荷小悦连锁后台：门店日常作业 PRD v1

日期：2026-10-24。基线 main：`26fff1c8243dcf845c2f507a3e82ce659fa7aa12`。本轮只做未提交候选和交互预览，不合并、不发布。代码位于 hxy 已核验独立工作区；旧修改保留。

## 目标与业务边界

顾客先选项目，座位可后安排。店员接收选单，店长跟进服务安排、加选、异常和评价；技师完成履约并填写本人服务记录。智慧宝负责物理开房和离位，DIY 不替代物理资源系统。本轮不做支付、收款、退款，不调整价格、会员权益或权限。店长与技师仍使用同一移动应用，按权限呈现；本批优化桌面后台，没有另造手机端。

总部维护目录、品牌内容、门店与账号；门店人员只处理本店业务。目录编辑上一批 #380 已上线，本批先解决日常接待里遗漏待办、误判空闲、按钮走错和失败无法恢复的问题。

## 页面与交互要求

### 今日工作台

- 指标为今日选单、待服务、服务中、今日完成。复用 summary 原字段；今日选单按创建日统计，待服务与服务中是当前状态量。未知与失败显示横线，不能补0。
- 主区域为门店待处理，每项写问题、范围与下一步。异常逾期是异常子集，不相加伪装独立总数。
- 补记录抽屉仅显示近30天技师姓名与数量，并指引本人在“历史服务→只看待填写”补填。店长不代填私人记录。
- 服务核对摘要只读。到服务待办点击“核对最新服务”才调用现有同步接口，不把GET当成已同步。
- 工作台、在店服务、核对摘要分别失败；其他已加载部分可继续查看。只读员工仍只查看今日安排。

### 服务待办

- 默认未处理 = open + acknowledged；切换待核对、已知悉、处理记录只读。
- 确认知悉后仍保留，标“已知悉·待处理”，不可说已解决。
- 跟进抽屉显示业务问题、关联标识、处理人、时限和时间。未知类型用通用中文，不直接展示JSON或内部码。
- “由我跟进”复用 assign；“保存处理结果”复用 resolve，需2–500字，失败保留草稿，成功进处理记录。进行中防重复点击。
- 保存仅关闭该待办，不修改原选单、服务进度或金额；明确提示原问题若仍存在可能再次出现。
- 达到接口200条上限提示“最近200条”，不伪称完整历史；加载失败不可显示暂无问题。

### 到店选单

- 确认提示“确认本次服务项目与金额；未入座也可先确认，座位稍后安排”。接口行为不变。
- 顾客扫码/到店选购等来源中文化，未知来源通用显示。
- 列表、加选、座位加载错误分别可重试。筛选迟到响应不得覆盖当前筛选；切换顾客后旧参考不得覆盖新顾客。
- 不顺带重写赠送权益、定价、取消或服务记录投影。

## 视觉规范

复用已定品牌变量：白内容区、深绿主按钮、浅绿辅助。标题24px、正文14px、指标26px；待办用可扫读表格与侧栏，不堆大数字/装饰卡片。窄屏表格可横滚但整页不可溢出。错误信息说明业务影响并给恢复按钮。

## 验收与交付边界

1. 正常、部分失败、列表空、未知状态均可预览；失败不显示成功结论。
2. 知悉后仍在未处理；保存处理结果后移入处理记录且可看原文；失败不丢输入、重复点击只发送一次。
3. 待办入口分别到对应页面；补记录按技师汇总，只读员工不调用管理接口。
4. 选单筛选与顾客参考迟到响应不串页；真实空列表与请求失败可区分。
5. 定向单元测试、实际页面组件浏览器交互、TypeScript编译和桌面/窄屏截图；预览只用合成模拟接口，非白名单请求拒绝。
6. 无后端或数据库变更、无提交合并发布、旧数据不动。上线前还需真实隔离API写入回读、门店与权限合同及必要CI；本预览不等于这些已通过，手机现场仍由人验收。
