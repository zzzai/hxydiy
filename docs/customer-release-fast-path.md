# 顾客端发布：快速且可核验

适用：已明确授权发布的顾客端改动。数据库迁移、凭证或跨端业务调整另行评估；不借提速扩大范围。

## 固定输入，减少重复工作

1. 读取上下文清单、当前状态和顾客端 workstream，核对 Git 状态；保护未提交修改，从最新主干开始。
2. 本地完成测试、构建、差异检查及针对性浏览器验证，锁定提交 SHA。介绍排版的浏览器检查按页面类型、身份、屏宽一次批量运行。
3. 创建 PR；GitHub 检查期间并行准备服务器独立工作区。合并后核对主干与已验证源码 tree 一致，变更后必须重验受影响部分。
4. 缓存复用前比较 lockfile / requirements；一致才复用依赖。需要下载时使用用户指定的国内镜像，不升级服务器系统运行时。源码归档保持 LF，避免 Windows CRLF 破坏 shell 脚本。
5. 服务器先构建再运行包含 dist 图片断言的顾客端测试；执行服务器验证。既有静态图片和未改动端的构建从实时 current 保留，不用历史文件名猜测。

## 发布与记录

- 先确认自动发布状态，避免自动与手工同时切换。手工发布使用项目已有 `deploy/diy/deploy-production.sh`，保留备份恢复演练、迁移拦截、Manifest、原子切换、容器更新和失败回滚。
- 发布后批量检查首页、健康接口、实际入口引用的 CSS/JS 和关键图片；核验 current、镜像、迁移 head。未执行数据库迁移时明确记录。
- 更新 CURRENT-STATE、顾客端 workstream、WORK-STATUS 和现有生产记录合同测试，合入主干才算共享事实。

## 节省 token 的输出方式

- 完整日志存于本地或服务器任务目录；成功只返回通过数量、SHA、产物名。失败只读取报错附近，不反复打印整份日志。
- 一组检查一个调用，独立检查可并行；CI 在准备工作期间运行，避免高频轮询。
- 不反复读取完整历史或已确认不变的源文件；依靠精简 CURRENT-STATE 和定向搜索。
- 不宣称固定节省百分比，实际耗时取决于 CI 排队、依赖缓存和网络。不能用跳过验证、覆盖现有修改或省略备份换取速度。

当前可进一步优化项：自动发布曾在固定主机密钥配置步骤失败。修复该配置后可减少人工接管，但主机指纹必须独立核验，不得关闭 SSH 主机校验或把密钥写进文档。
