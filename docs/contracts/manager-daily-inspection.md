# 店长每日巡检照片

营业日期按北京时间计算，店长在本人门店的「巡检照片」入口操作。各店共有六个必拍点，分别为卫生间、打水房、收银台、休息区、足疗区、煮药区。每区至少一张有效照片，最多三张。当日清单所有拍摄点齐全且已上传晨会录音，日报可提交。

## 华富世家店的清单

门店编码 `hxy-anyang-huafu-002` 新建的日报固定使用第 3 版清单。除六个公共拍摄点，还要拍仓库、淋浴间，以及 SPA 房的半夏、忍冬、杜若、青黛，共 12 个拍摄点。仓库和淋浴间各需 1～3 张，四间房每间单独拍 1～3 张。照片的拍摄回执和三个槽位均按具体拍摄点校验。一间多拍不抵另一间漏拍。房间按房名展示，拍摄前确认空场。

紫薇壹号店继续使用六点清单。已有版本的日报（含已经打开的当日草稿）继续使用首次创建时的版本。旧五区历史与旧六区日报按其原版本查看或提交，无需补图。新版四间房在 `areas[]` 分别使用 `spa_banxia`、`spa_rendong`、`spa_duruo`、`spa_qingdai` 和可选的 `group=spa_rooms`。仓库与淋浴间分别为 `warehouse`、`shower_room`。`completion.areas_done/areas_total` 统计必拍点，店长可在 SPA 房下看到已拍房间数。

## 店长手机巡检页

首屏显示当日拍摄进度和晨会录音入口。拍摄清单支持按全部、待拍、已拍筛选。华富公共区域与四间 SPA 房分组计数，紫薇使用本店清单。点待拍区域可立即打开现场相机。已有照片的区域可展开原图、逐张审核结果与更换入口，亦可继续补拍至三张。已拍与审核结论分别展示，提交条件沿用各拍摄点的照片和晨会录音。

## 读写约定

- GET `/api/v1/admin/v2/manager/daily` 返回 `business_date`、`max_photos_per_area`、`completion.areas_done/areas_total` 和每区按槽位排序的 `photos[]`。每张含 `id/slot/media_id/media/note/captured_at`。`photo` 保留首张兼容投影。完成数按有有效照片的区域计算。
- 每个区域在手机相机预览中拍摄新图，更换也需要重新拍摄。相机不可用时可重试。POST `/api/v1/admin/v2/manager/daily/camera-captures` 接受当日区域的 JPEG 帧并复用媒体校验，返回媒体 ID 和绑定门店、店长、区域、营业日及媒体的 15 分钟签名回执。新关联须带 `capture_receipt`；普通媒体上传和缓存的旧客户端不能把相册图片挂入巡检。当前槽位同媒体的幂等重试可沿用已有记录。Web 相机约束的是页面输入来源，不提供设备级拍摄地点认证。
- 上传用途为 `daily_area`，保存使用 POST `/api/v1/admin/v2/manager/daily/photos`。追加传 `mode=append`、区域、媒体 ID、当前营业日期。重复关联同区同一媒体幂等，第四张返回 409。相同媒体不能充当多个区域的新版证据。
- 指定更换传 `mode=replace`、目标照片 ID 和原媒体 ID。媒体已经变化时返回 409。只更新选定槽位。更换封面、指定更换和追加的新图都须提供现场拍摄回执。实际编辑已提交的当日记录会重新开启草稿，重复提交及重复关联保留原提交时间。
- 后端按门店及营业日串行处理，同一营业日首次建单也受保护。数据库限制每区槽位 1～3 且唯一。当前日期已变化、媒体跨店或用途不符时不关联。旧五区正式提交记录和历史营业日使用原清单；升级时仍在当日的草稿继续已有照片，补拍煮药区后可提交。
- 迁移增加清单版本和照片槽位，不回填旧巡检业务字段。旧图占第一槽。已有新版记录时拒绝降级，以免丢图。照片访问和原有保留期沿用既有系统。日报提交条件仍按照片和录音判断。

## 日常自动处置与企微周报

门店负责现场拍摄和整改，系统负责初审、通知、复查和结案。总部或指定负责人每周通过企微看一次两店汇总。新流程覆盖紫薇壹号店、华富世家店。原图拍摄时间达到启用界线后，符合条件的异常进入本店待办。先前人工更正保留原记录。

- **门店当天怎么做。** 初审通过即归档。系统将需整改或需补拍的区域、画面依据及处理建议通过企微发给本店店长。店长完成现场处理，从原问题入口重新拍照。系统对照同一门店、区域及原问题自动复查，新图能证明已经解决才结案。画面仍有问题或拍不清原位置时，继续给门店明确的下一步。日报提交与问题结案分别记录，跨营业日仍可追踪原问题。
- **判断依据。** 保留原图、复拍图、各次结论及时间。审核服务失败沿用受限重试，重试耗尽列入「审核未完成」。需补拍反映照片不足，单列于卫生整改。新流程由服务端执行，旧版店长端也无权把问题直接改为通过。既有人工更正作为历史事实展示，与系统已验证的整改分别统计。
- **总部每周看什么。** 按北京时间汇总上一完整自然周（周一至周日）。每店列出提交天数、实际拍摄点覆盖情况、需整改及需补拍的问题数、复查通过数、期末未解决数。按门店和区域指出反复出现的问题、与上周的变化，以及有记录支持的下一步建议。按同一问题归集多次复拍；同一区域重复出现按不同营业日计数。覆盖率按当日实际清单计算。营业安排或环比样本欠缺时展示实际计数及数据缺口。审核故障单列。
- **企微发送。** 门店日常消息仅送本店对应账号，总部只收周报。周报以已核实的企微绑定投递汇总，不含员工、顾客明细或原图。接收周报无需增加跨店后台权限。同一问题状态和同一周报对同一接收人各发送一次，保留发送回执，区分明确失败与回执未知。
- **复拍接口。** 今日巡检的 `open_issues` 包含本店在保留期内仍待处理的问题，可以跨营业日操作。现场拍摄时在 `camera-captures` 传原问题 `issue_id`。POST `/api/v1/admin/v2/manager/daily/issues/{root_id}/followups` 接收 `media_id`、`capture_receipt` 和上次看到的 `expected_review_id`。同次回执重复提交返回既有结果，另一张照片基于过时结论提交会被拒绝。新证据关联到原问题，不占原日报的拍摄槽位。新图和原图适用同一访问范围与保留期限。
- **发送时间与回执。** 北京时间周一 09:00 起发送上一完整周的汇总。若定时进程停机后恢复，检查最近一期到期周报。周报在排队时保存正文。服务商确认接收、明确拒收、结果未知分别记账；结果未知不自动重发。投递配置单独绑定已核实企微账号与绑定版本。账号失效时保留记录，日志记录失败类型。企微接收回执只证明接口接收。
- **验收。** 两店分别验证现场复拍、旧客户端改判被拒、自动复查通过或继续处理、审核失败及跨店隔离。以留存样例验证人工改判从系统整改通过数中剔除。按周边界重跑汇总，验证发送去重、门店企微收件范围和总部每周单次收件。

## 逐张自动审核

照片关联到区域时进入审核队列，队列与照片在同一事务中提交。服务启动后会持续查找 90 天保留期内遗漏的巡检照片，包含功能启用前上传的照片。仅处理同店、仍在当前槽位、未删除的巡检图片。每个照片和媒体 ID 组合只保留一个审核任务。已出结果的原图沿用已有结论。换图后只展示新图的结果。

店长可在当天巡检或「查看过往巡检照片」直接看到审核进度、结果和建议。当前打开的日期有待审照片时会自动刷新。审核由服务端执行，门店人员离开页面也会继续。

每个拍摄点按所属区域使用观察标准。仓库看货架、堆放和通道，淋浴间看可见地面、排水口与置物台，SPA 房看床面布草、用具与通道。煮药区看锅台、锅沿、料架和用具，其他区域各看本区域的可见整洁与归位情况。缩小图片并移除元数据后，服务端将图片和标准发往 DeepSeek 官方视觉接口。结果有「通过」「需整改」「需补拍」，包含画面位置、可见依据以及下一步。照片有结果即可使用。如现场照片与判断有出入，店长在原问题下重新实拍，系统对照画面复查。初审不认定消毒效果。

- GET 的 `inspection_ai_enabled` 表示初审可用。每张照片含 `reviewable` 与可为空的 `review`。结果按当前媒体投影。
- 旧版客户端兼容调用 POST `/photos/{photo_id}/review`，携带 `media_id` 和 `expected_attempt`。首次请求历史图，或重试一次已失败的审核。进行中、已完成请求幂等。旧端 POST `/photos/{photo_id}/manual-review` 对本店有效照片返回 `409 INSPECTION_SYSTEM_REVIEW_ONLY`，跨店不可见。
- `pending/running/done/failed/superseded` 分别表示排队、审核中、有结论、未能完成、原图已更换。中断及服务商错误保留照片，遇到临时错误时，后台在第 2 分钟和第 10 分钟后分别重试，最多调用三次。`review.retry_scheduled` 表示仍有自动重试安排。不可读取的图片或重试耗尽时显示「AI 未能给出结论」。原图和审核关联沿用 90 天保留期。
- 生产通过 `INSPECTION_AI_ENABLED` 和已配置的 DeepSeek 账户开启。新旧照片统一按有效巡检范围处理。独立开关可暂停外部调用。

## 店长晨会录音入口

「今日」的晨会待办和常用「录音记录」均打开 `/technician/store/recordings`。店长可录制、保存、按营业日期回听音频、查看文字稿和重试失败的转写。区域巡检保留晨会完成状态和录音入口，提交巡检仍检查当日照片和晨会记录。历史音频和文字稿沿用原有访问范围与保留期限。
