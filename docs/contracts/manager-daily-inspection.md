# 店长每日巡检照片

营业日期按北京时间计算，店长在本人门店的「巡检照片」入口操作。所有门店的新版必拍区域为卫生间、打水房、收银台、休息区、足疗区、煮药区。每区至少一张有效照片，最多三张。六区齐全且已上传晨会录音，日报可提交。

## 读写约定

- GET `/api/v1/admin/v2/manager/daily` 返回 `business_date`、`max_photos_per_area`、`completion.areas_done/areas_total` 和每区按槽位排序的 `photos[]`。每张含 `id/slot/media_id/media/note/captured_at`。`photo` 保留首张兼容投影。完成数按有有效照片的区域计算。
- 上传用途为 `daily_area`，保存使用 POST `/api/v1/admin/v2/manager/daily/photos`。追加传 `mode=append`、区域、媒体 ID、当前营业日期。重复关联同区同一媒体幂等，第四张返回 409。相同媒体不能充当多个区域的新版证据。
- 指定更换传 `mode=replace`、目标照片 ID 和原媒体 ID。媒体已经变化时返回 409。只更新选定槽位。旧客户端省略模式仍按原协议更换第一张。实际编辑已提交的当日记录会重新开启草稿，重复提交及重复关联保留原提交时间。
- 后端按门店及营业日串行处理，同一营业日首次建单也受保护。数据库限制每区槽位 1～3 且唯一。当前日期已变化、媒体跨店或用途不符时不关联。旧五区正式提交记录和历史营业日使用原清单；升级时仍在当日的草稿继续已有照片，补拍煮药区后可提交。
- 迁移增加清单版本和照片槽位，不回填旧巡检业务字段。旧图占第一槽。已有新版记录时拒绝降级，以免丢图。照片访问和原有保留期沿用既有系统。日报提交条件仍按照片和录音判断。

## 逐张照片初审

启用后，新上传的巡检照片在关联到区域时进入审核队列。一张照片对应一份结果，按照片和当前媒体 ID 绑定。队列与保存照片在同一事务中提交。启用前上传的媒体只在本店店长点击「审核这张照片」后送审。店长可在「查看过往巡检照片」按营业日期查看保留期内的原图，并点选其中一张。查看页面、打开历史、重复保存以及提交日报均不追加审核。更换照片时丢弃旧图的在途结果。

六个区域各有观察标准。煮药区看锅台、锅沿、料架和用具，其他区域各看本区域的可见整洁与归位情况。缩小图片并移除元数据后，服务端将图片和标准发往 DeepSeek 官方视觉接口。结果有「通过」「需整改」「需补拍」，包含画面位置、可见依据以及下一步。店长可对已完成或失败的初审作一次人工复核，两份结论分别保留。初审不认定消毒效果。

- GET 的 `inspection_ai_enabled` 表示初审可用。每张照片含 `reviewable` 与可为空的 `review`。结果按当前媒体投影。
- 本店店长调用 POST `/photos/{photo_id}/review`，携带 `media_id` 和 `expected_attempt`。首次请求历史图，或重试一次已失败的审核。进行中、已完成请求幂等。POST `/photos/{photo_id}/manual-review` 携带 `media_id` 和 `verdict`。媒体变化返回 409，跨店不可见。
- `pending/running/done/failed/superseded` 分别表示排队、审核中、有结论、未能完成、原图已更换。中断及服务商错误保留照片，失败不计通过，由店长选择重试或复核。原图和审核关联沿用 90 天保留期。
- 生产通过 `INSPECTION_AI_ENABLED`、首次启用时冻结的 `INSPECTION_AI_AUTO_FROM_EPOCH` 和已配置的 DeepSeek 账户开启。后续发布保留该时间。独立开关可暂停外部调用。
