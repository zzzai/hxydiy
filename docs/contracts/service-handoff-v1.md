# 技师服务交接 v1

状态：本地实现，待合并发布。结构版本 `7`，字典版本 `service_handoff_v1`。

## 目标

服务结束后，技师用少量点选留下下一次服务能直接使用的信息。记录不是完整顾客画像、医疗记录或营销标签，也不按填写数量考核技师。

## 写入范围

- `communication`：`quiet`、`chat`。
- `body_focus[]`：最多三项，每项必须同时保存 `region` 与 `next_action`。
  - 部位：`neck_shoulder`、`waist_back`、`leg`、`knee`、`foot`。
  - 下次动作：`focus`、`lighter`、`avoid`、`confirm`。
- `session_changes[]`：最多三项，记录本次真实发生的力度、温度、节奏或提前结束变化。
- `basic_info`：年龄段与性别均为选填。年龄段使用互不重叠的稳定编码；性别只提供 `male`、`female`，未选择即不记录。
- `private_note`：最多 200 字，仅创建技师本人可见。
- `recording_outcome=no_additional_notes`：与其他内容及顾客确认互斥。

年龄段编码为 `age_25_29`、`age_30_34`、`age_35_39`、`age_40_44`、`age_45_49`、`age_50_59`、`age_60_plus`。展示文案分别为 25–29、30–34、35–39、40–44、45–49、50–59、60以上。

## 安全与可见范围

- 写入必须关联当前门店、当前顾客、创建技师本人已完成的服务，并保留幂等与审计。
- 本人可以针对同一次服务追加一次更正，原记录不覆盖。
- 其他技师只读取经顾客确认的沟通方式、部位对应的下次动作和本次调整；自由文字、年龄与性别不进入交接摘要。
- 管理端不接收自由文字、年龄、性别或具体身体部位；存在身体条目时只获得“服务前再确认”提醒。
- v7 不写入 `customer_profile_current`，不转换为普通标签，不用于定价、分群、自动营销或算法训练。
- v1–v6 历史记录保持只读兼容，不自动转换为 v7。

## 会员核验顺序

技师先扫描顾客动态会员码，再读取本店待核验服务单。只有一个候选时自动匹配，多个候选时由技师选择；最终消费接口仍必须提交 `selection_session_id`，原有门店、会员、动态码、价格、幂等与审计校验不变。
