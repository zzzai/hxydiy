# 员工学习接口契约 v1

状态：基础学习与 12 课已启用；2026-11-17 增补每日流程契约，实际发布以 CURRENT-STATE 和精确回执为准。历史 PRD：../product/learning-workbench-live-v8-20261027.md。

## 身份与范围
沿用现有员工 JWT 和服务端即时身份复验，不新增登录方式。店长只能访问当前门店；技师只读写本人学习任务，仍须有同店有效技师档案。总部身份没有学习全店查询入口。拒绝请求参数覆盖门店/身份；停用账号、跨店访问与角色越权拒绝。店长不能代读、代答、改分，技师不能安排课程或写店长建议。

## 接口
前缀 /api/v1/staff-learning。所有接口要求员工认证。
- GET /status：返回 enabled；不启用时不查询学习表。
- GET /bootstrap：actor、assignments、courses、roster、assignableCourses。技师只有本人任务及对应课程，roster/assignableCourses 为空；店长只有本店任务和有效本店技师名单。
- POST /assignments：staff_id、course_id、course_version、request_id。仅店长；一个门店同一员工同一课程版本只生成一个任务。
- POST /assignments/{id}/actions：kind、request_id、expected_revision。mark_section 仅带 section_id；submit 仅带 answers；follow_up 仅带 note。拒绝多余字段及客户端分数。

课程公开题目只有 id/prompt/choices，不包含标准答案和解析。交卷后仅通过本人任务或本店店长可见的 attempt.review 返回标准答案、解析。判分由服务端进行；练习得分不是实操达标或项目上岗资格。

## 保存与冲突
员工行及任务行加锁；版本匹配后追加事件并递增 revision。request_id 在门店、执行员工范围唯一，精确重复请求不重复写；同键异内容返回 409。先校验当前身份和范围，再识别重复请求，不能通过重放绕开权限。重复成功请求回读当前快照，不保证返回最初时刻的旧快照。
两个店长同时给同一员工安排同一课程版本，由唯一约束兜底，只生成一个任务。答题必须完整、整数选项有效且逐节学习完成；重复交卷只追加一次尝试。新一次练习保留旧成绩。店长建议只追加，不覆盖练习或他人的意见。

## 课程与状态
课程版本内容与 SHA256 绑定，内容漂移返回冲突。pilot 仅 local/test 可用；published 还要求非空审核依据。retired 课程历史只读，不接受新动作。正式内容通过 `scripts/publish_staff_learning.py` 精确 SHA 预览后发布或停用；不提供页面改题或专业实操认证。批准引用记录用户的内容投产指令，不等同医疗专业审核。
学习状态由阅读节数和历次练习推导：未开始、学习中、已读待练、需复习、练习全对。没有以页面停留时间、勾选或练习全对自动授予实操资格。客户端不持久保存学习记录，刷新从服务端回读。

## 数据存储
仅新增 learning_course_versions、staff_learning_assignments、staff_learning_events；外键引用 stores/staff，不改订单、会员、余额、服务记录。事件记录执行人、内容、请求摘要、任务版本和时间；无修改/删除事件接口。

## 开关与迁移
后端 STAFF_LEARNING_ENABLED 默认 false，前端 VITE_STAFF_LEARNING_ENABLED 默认不启用；两个开关都开启才正式可用。本次预览通过专用测试入口注入组件，生产默认入口不变。
迁移 20261027_staff_learning 接在 20261026_coupon_budget 后，仅建三表及索引。具体投产/回退步骤见 PRD；用户 2026-11-02 已明确授权真实备份和隔离恢复验证后的三表增量迁移、12课36题导入与启用；未完成验证不得直接迁移。

## 2026-11-17 每日安排与辅导复练

- 复用当前 12 课 36 题；不编辑课程、不补写旧答卷、不创建新表。StaffLearningAssignment 继续是同店/同人/同课程版本唯一档案；每日安排是在既有 assign 事件中追加 daily_plan（learning_date、due_at）。原 sections_read、答题和辅导历史保留。
- POST /assignments 新增可选 learning_date（YYYY-MM-DD）、due_time（HH:mm），必须成对。统一北京时间，允许今天至未来30天，首次安排时截止时间必须在未来；默认 UI 为当天23:59。同人同课同日同截止时间返回已有计划，变更截止时间返回409；不覆盖原安排。员工行、目标技师行、课程档案行按顺序加锁；不同店长并发只生成一份每日安排。
- 原未带日期的接口和旧幂等摘要兼容；它们不计为新日任务完成。相同 request_id 的精确成功重放仍回读当前快照，不受日期已过影响；同键异内容409。不同 request_id 的同日重复安排仅追加引用已有计划的审计回执，不生成第二份计划。
- bootstrap 增加 dailyTasks、learningToday、serverNow；assignments 保留兼容。dailyTasks 每项 dailyPlanId 绑定 assign 事件；展示 id 为 daily:事件ID、assignmentId 为原档案ID。旧未按日任务单独显示“历史学习”。新日进度只读取 payload.daily_plan_id 与该计划一致的事件，旧成绩不能抵扣新日进度。
- actions 增加可选 daily_plan_id；必须属于路径档案及当前本人/门店。未来日期不接受读完、交卷、辅导；已过截止可以补学，标记逾期或补学完成。日期和状态来自服务器，不能按浏览器时区判断。
- 每日状态：scheduled、not_started、in_progress、ready、needs_coaching、needs_retry、completed。提交全对且晚于最后一条辅导事件才完成；答错待辅导，店长追加建议后待复练，再次答错回到待辅导。没有答卷或已完成的每日任务不能新增辅导，防止空辅导或意外重开。所有尝试与辅导保留，无改分/删除接口。
- 店长按日查看已安排/完成/未完成任务数，以及本店可安排但当日未安排人数；后者不能被算作已完成。筛选待辅导、待复练、当日全部；逾期筛选跨全部日期。刷新从服务器读取。技师首页显示当天任务与逾期未完成，未来安排和历史分开展开。
- 既有 manager-daily/team 读取同一日任务投影：有日任务后，以今天和逾期未完成集合判断完成/逾期及实际截止时间；不能沿用旧成绩或“首次安排+7天”判断。没有日任务的历史档案维持原口径，不写回它们。
- 总部学习治理现有 assigned/completed 仍是课程档案/曾提交统计，并非当日完成率；每日任务运营以团队学习页为准。
- AI教练仍只在主动提问时调用；AI周计划是草稿，点击安排才按所选日期和截止时间创建任务，不自动派课、不发送外部消息。答题成绩不自动授予实操资格或影响工资。

验收采用独立 PostgreSQL、合成员工、真实 HTTP 完整应用和手机尺寸浏览器；与真实手机/企业微信现场验收分开。发布前后核对生产旧行与结构，测试账号和成绩不进入生产。
