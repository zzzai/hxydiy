# 顾客端本店技师

## 已确认的照片弹窗

2026-11-25 确认以下互动样页。人物、工作照和点名选单均为模拟。正式页面复用门店公开资料和逐份点名。下列样页保留作视觉参照。

[打开离线互动样页](../design/evidence/technician-photo-popup-20261125/prototype.html) · [点照片前后的手机对照](../design/evidence/technician-photo-popup-20261125/roster-and-drawer.webp) · [上滑查看可点项目](../design/evidence/technician-photo-popup-20261125/requestable-projects.webp)

- 从「看技师」名单点照片，手机从底部展开资料，宽屏居中弹出。首屏给出大人像、已确认的从业年限和已有的公开工作照，向下阅读可见服务风格、可点项目、时长及门店价。点照片可放大，退出大图回到该技师资料。正式展示沿用下文的公开资料和示意图标识规则。
- 从筛选并滚动过的名单打开再关闭资料，原筛选和滚动位置保留，焦点回到刚才的技师卡片。只浏览或放大照片时，选单保持原样。
- 从名单点名要先选具体项目。从已有项目进入时只作用于正在编辑的那份服务。验收时在同一房间为两位顾客各选一份相同项目，分别点名两位有资格的技师。提交后，店长端应能核对每份服务及其对应的点名，最后由店长确认。

## 现有实现

顾客可从底部「看技师」或单份项目的服务技师区进入本店名单。名单展示已公开的服务风格，可点击筛选。点卡片展开照片资料，手机底部展开、宽屏居中。点照片进入大图；返回恢复照片焦点，再关闭资料恢复原筛选、滚动位置和技师卡片焦点。浏览及放大照片均为只读操作。顾客从个人资料选择具体的可点名项目时，先复核该店该项目的资格，再将所选技师带入新一份项目草稿。顾客从已有项目进入技师名单时，点名仅回填正在编辑的那份草稿。两种入口均须由顾客确认项目、提交选单，再由店长确认点名。

弹窗顶部展示公开称呼、已有的从业年限和门店。首屏优先放公开肖像与工作照。只有一张时单图展示，多图可切换放大。缺少真实公开照片时使用带「AI 示意 · 非本人」标识的示意图，放大时也显示标识。服务风格、介绍和可做项目取自本店公开资料。可点的项目排在前面，项目行显示已有的时长及门店价。当前不能点名时提供门店安排说明，只有配置了官方企微的门店才显示联系入口。地址和营业时间仍可展开查看。

## 公开资料

`GET /api/v1/stores/{store_id}/technicians` 仅接受营业和试营业门店。返回 `items`，每条包含门店内稳定的 `key`、公开称呼、可选的已确认从业时间、肖像、服务标签、介绍、工作照及本店公开项目 ID。手机号、员工登录名、入职日期、佣金、内部备注和未公开媒体均不投影。从业年限以门店确认的资料为准。没有真实照片、评价、从业年限或服务标签时，相应内容留空。

门店可在版本化的 `hxy-server/content/public-technicians.json` 中维护已经确认用于顾客展示的内容，按完整 `store_code` 分组。肖像和工作照仅使用该门店 `diy-web/public/assets/technicians/<store_code>/` 下获准公开的图片。更新图片使用新的文件名。没有明确绑定的公开工号可以展示，`technician_id` 为 null，两份项目列表为空。工号保留前导零。配置绑定必须指向同店正式技师，停用、离职、模拟和管理账号均不进入顾客名单。首次发布的华富六份资料只含工号和已确认从业时间。

正式账号的 `project_ids` 取自已登记技能与本店独立公开项目的交集。只有符合原点名条件的项目才进入 `requestable_project_ids`。休班技师可查看公开资料，点名集合为空。点名会再查询该项目的实时可选名单，保存和提交沿用服务端的逐份资格校验。可提交点名不代表已经排钟。门店名册中的工号与业务技师 ID 不做数值匹配。
