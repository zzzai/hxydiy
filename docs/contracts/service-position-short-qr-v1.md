# 服务位短链接二维码契约 v1

更新日期：2026-09-23

## 码面与解析

- 新生成或重新读取的服务位二维码使用 `https://diy.hexiaoyue.com/api/v1/q/{short_code}`。`short_code` 是 16 字节、URL-safe Base64 编码的 22 字符 bearer code；不包含门店号、服务位编码或可猜业务序号。
- 短码由服务端密钥和二维码记录的随机 UUID 生成，具备 128-bit 级不可猜测空间。数据库只保存短码的 SHA-256 哈希及唯一索引，不保存短码明文。
- 公共解析接口只接受格式正确且哈希命中、状态为 active、绑定仍一致且服务位启用的短码；成功后以 HTTP 307 跳转到既有 v3 签名 H5 入口。短码不能自行指定或覆盖门店、服务位和来源。
- v2/v3 已打印长码继续兼容；短链接只缩短码面，不改变顾客菜单、共享草稿、提交、评价或会员权限。

## 生命周期与并发

- 管理端 `GET /api/v1/admin/service-positions/{room_id}/qr-link` 返回短 URL，同时继续返回现有 v3 `token` 供兼容调用。首次读取历史二维码时只补写哈希；重复读取返回同一短 URL。
- 创建和补写短码在服务位行锁内完成，哈希具有数据库唯一约束。停用、重新生成或换绑沿用二维码记录的既有状态机；旧短码立即拒绝，重新生成的新二维码得到不同短码。
- 本次数据库迁移只增加可空 `short_code_hash` 及唯一索引，不轮换、不停用、不改绑现有二维码。现有记录由授权管理端读取时惰性补写；生产 8 个沙发码在新入口部署验证后从现有 active 记录导出短链接图片，不轮换底层记录。

## 安全、审计与限流

- 短码属于 bearer credential，知悉链接者可在二维码有效期间访问对应服务位入口；不得把短码当作顾客身份或直接授权其他门店、床位、订单、会员信息及评价。
- 每次成功解析写入 `service_position_short_link_resolved` 审计，记录二维码、门店、服务位及 HMAC 化请求来源，不记录短码明文。
- 同一来源、同一二维码每小时最多解析 300 次，超限返回 HTTP 429 `QR_RESOLVE_RATE_LIMITED`。后续菜单加入、共享写入和到店反馈仍继续执行各自既有限流、令牌绑定及权限检查。

本契约不证明现场扫码验收。生产发布需经过迁移备份、恢复演练、精确提交部署和公网解析验证；8 张新码导出、打印与逐位真机核对应单独记录。
