# 顾客端服务位共享选单契约 v1

更新日期：2026-09-23

## 入口与共享范围

- 每个启用的服务位使用自己的 v2/v3 签名二维码。扫码首屏直接进入项目菜单；「评价与建议」是菜单内次级入口。
- 新物料优先使用 `service-position-short-qr-v1.md` 的短 HTTPS 链接；服务端解析后仍进入本契约规定的同一 v3 签名入口，既有 v2/v3 长码保持兼容。
- 同一服务位、同一活动占用只存在一份未提交选单。任何浏览器扫描同一有效二维码均加入该草稿，可增删项目。
- 浏览器即使仍绑定其他服务位，扫描目标服务位的有效签名二维码时，只要目标服务位已有活动占用，也直接加入该服务位并进入菜单；原服务位不会因此被释放或覆盖。若目标服务位为空，仍拒绝同一浏览器同时占用两个空服务位。
- 有效签名二维码指向仍启用且门店状态为“有人”、但没有活动 DIY 选单的服务位时，服务端为该位置创建一份新草稿并返回 `entry_notice=该位置当前有人，已进入菜单`；顾客端以轻提示承接后直接展示菜单，不再显示整页阻断。该例外不适用于空闲座位、暂停使用、清洁中、维修中或未签名入口。
- 每次扫码签发独立、绑定当前 HttpOnly `hxy_browser_token` 的协作者令牌。协作者令牌只授权当前门店、服务位、二维码、活动占用和选单，不返回其他顾客身份、会员状态、会员价格、订单或评价。
- 协作者令牌默认 12 小时有效；二维码停用、轮换、改绑，活动占用结束或服务位变更后立即失效。入口和写操作沿用服务端限流与审计，不以可复制的静态二维码充当顾客身份。

## 并发与提交

- `POST /api/v1/entry-sessions` 对已存在的未提交草稿返回同一 `session`，并返回当前浏览器独立的 `collaboration_token`、`collaboration_mode=shared_draft`、`cart_version` 和 `shared_cart=true`；上述“有人但无活动选单”入口额外返回可空 `entry_notice`。不得旋转选单全局访问令牌使其他设备失效。
- 协作者读取、保存、报价和提交分别通过 `X-Collaboration-Token`；保存和提交必须携带响应中的 `expected_version`。
- 服务端在事务内锁定选单与占用。版本不一致返回 HTTP 409、`CART_VERSION_CONFLICT`、最新 `cart_version` 与去身份化的最新选单快照；不得静默最后写覆盖。
- 提交通过 `Idempotency-Key` 幂等。首次成功后选单与占用状态原子推进并增加版本；同键同请求重放返回原结果。其他协作者立即只读，追加、改价和确认继续走既有受控修订流程。
- 再次扫描已有已提交清单的服务位返回 `collaboration_mode=browse_only`，首屏仍为菜单，但响应清空项目、价格和计价快照，不能读取或修改已提交清单。
- 顾客端对已有未提交选单只显示一次轻提示后进入可协作菜单；对已有已提交清单只显示一次轻提示后进入只读浏览菜单，不再展示“这个位置已经有人”的全屏阻断页。

## 评价边界

- 本人已完成服务的评价继续要求原选单凭证或本人登录所有权及权威服务完成状态。
- 匿名或无订单顾客使用签名二维码签发的 `visit_feedback_token` 提交独立到店反馈。
- 共享草稿能力不能用于读取或提交他人的服务评价，也不得暴露他人订单、会员身份/价格或个人信息。

## 固有风险与现场控制

静态二维码被拍照后，照片持有者在令牌有效期内可能远程加入尚未提交的共享草稿。这是允许多人扫码共享所带来的固有风险，不能通过前端文案消除。控制措施为最小字段投影、浏览器绑定、12 小时有效期、提交即锁、二维码停用/轮换即时失效、入口/反馈限流和服务端审计。门店发现码图外泄时应先停码或轮换，再重新打印张贴。

本契约不证明生产发布或门店现场验收；微信真机、弱网、多人同时增删、重复提交和停码后的旧照片均须单独验收。
