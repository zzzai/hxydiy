# 顾客发券策略暂停

2026-09-05 用户决定：移除匿名顾客送券引导，暂时停止新增发券策略。

- 后端 `COUPON_ISSUANCE_ENABLED` 默认 `false`，暂停新客自动赠券、主动领券、分享赠券与邀请奖励。
- `GET /api/v1/coupons/templates` 返回空列表；已登录顾客调用 `POST /api/v1/coupons/claim` 返回 409，错误码 `COUPON_ISSUANCE_PAUSED`；匿名调用继续返回 401。
- `POST /api/v1/coupons/claim-share` 返回 `granted: false`，不会新增券记录。
- 报价不再返回 `kind: coupon` 的登录引导；会员价差提示保持原有规则。
- 顾客端停止详情页领券引导，并忽略旧服务端的券类提交前提示，提交路径继续正常工作。
- 已发券、券模板及审计数据保留；我的券查询、原有券有效期、结算使用与门店活动价格保持原规则。
- 恢复策略需要同步后端开关与顾客端引导，不能只重新发布券模板。

已通过 PR #23 合入主干，并随 `manual-8912faf-20260905-3` 发布生效；后续状态以 CURRENT-STATE 的实际发布记录为准。

## 2026-10-23 固定面额券预算与并发边界

- 预算是当前模板的发放上限，不是财务流水。固定面额券以该模板全部 UserCoupon 张数（含 unused、locked、used、expired）×面额计占用；使用、过期不释放预算。NULL 仍表示不限预算。
- 手工发券、主动领取、分享领取、新客自动赠券、邀请奖励共用模板行锁与预算检查；检查、写券、原审计/业务提交处于同一事务。涉及顾客的发放先锁顾客再锁模板；新客批量模板按 ID 顺序加锁。首单邀请奖励在启用策略时先按顾客 ID 顺序锁购买人与邀请人，再检查首单和锁模板，避免互为邀请人时订单外键检查形成死锁。
- 手工发券与主动领取超预算返回 409 / COUPON_BUDGET_EXHAUSTED；分享领取返回 granted=false；新客、邀请奖励跳过本次发券，不因预算耗尽阻断登录或下单。
- 模板更新也使用同一行锁。有已发券且原预算或更新后预算任一非 NULL 时，修改 amount_cents 或 coupon_type 返回 409 / COUPON_ISSUED_VALUE_IMMUTABLE；同值提交仍允许。不增加券面额历史快照或数据库字段。
- 预算可按原权限调整或设为 NULL；调低到既有占用以下不会回收旧券，剩余额度按 0 展示，继续发放被拒绝。关闭预算不新增永久历史锁定机制。
- 本次不改变折扣券既有行为，不为 auto_apply 活动展示新增结算预算系统，也不禁止旧配置组合。固定券预算覆盖实际 UserCoupon 发放，不扩展为活动优惠成本。
- COUPON_ISSUANCE_ENABLED 默认暂停、会员限制、门店归属、每人限领及分享 24 小时/邀请每日限额均保持原边界；手工管理发券仍沿用原有管理权限，不受顾客策略开关新增限制。
- 验证使用合成 SQLite 与隔离 PostgreSQL，包含跨顾客/跨入口并发、模板修改互斥和锁后旧快照刷新。本次未启用任何生产发券策略；生产生效以 CURRENT-STATE 的发布记录为准。

## 2026-11-13 管理端券规则与统计契约

- `percent_off` 表示减免百分比，20 = 减免20% = 8折，50 = 5折；前端不得再以 `percent_off / 10` 显示折数。金额一律以整数分存储和计算，展示允许必要小数。
- 创建/修改必须校验类型、状态、金额、比例、门槛、有效期、每人限领和预算；`percent` 缺少合法比例返回 422 `COUPON_CONFIG_INVALID`，错误字段在 `detail.fields`。历史异常模板仍在列表显示 `config_warnings`，不批量改写旧数据。
- `budget_cents` 的 `null` 表示不限、`0` 表示零预算、正数表示上限。零预算与空预算在输入、保存、回显和发放限制中必须区分；固定面额预算占用仍为全部已发 UserCoupon（含 unused/locked/used/expired）×面额。
- 券规则读取允许店长读取本店，普通员工/技师拒绝；券规则创建、修改、发布、下架只允许总部/品牌管理员（`role=admin` 或品牌管理员工作区），店长保留本店发券、核销、记录读取和导出。不得通过扩大 `_require_admin` 影响其他运营接口。
- 后台读取与写入均以服务端门店 scope 为准；直接 API 越店返回 403，详情/导出不泄露他店数据。
- 券台账按当前有效状态区分 `unused/locked/used/expired`，原始 `stored_status` 保留供审计；查询时按当前时间计算过期，不批量修改历史 status。
- 核销记录按 AuditLog 的真实核销时间独立筛选，不先按领取时间裁券；领取批次统计与核销事件统计不得混算为转化率。
- 券模板创建、修改、发布、下架、预算调整在同一事务写 AuditLog，包含动作、actor、门店、变更前后值和 request_id；不记录 token 或完整手机号。失败不得留下半条业务写入。
- 管理端新增规则/台账/海报/核销读取模型、分页和脱敏 CSV 导出；导出使用筛选后全量结果、统一权限、脱敏手机号、CSV 公式注入防护并写导出审计。

## 2026-11-13 券报表日期边界

- 券运营概览和核销记录保留 `days` UTC 滚动窗口作为默认兼容行为，`period.mode=utc_rolling_days`、`timezone=UTC`。
- 新增可选 `start_date`/`end_date`（`YYYY-MM-DD`）时，按 `Asia/Shanghai` 自然日解释，并显式换算为 `[start 00:00 +08:00, end+1 00:00 +08:00)` 的 UTC 查询区间；响应 `period.mode=asia_shanghai_natural_day`，同时返回 UTC 起止时间。
- 开始/结束必须同时提供，范围最多 90 天；不得静默改变旧 `days` 接口含义。概览和核销记录使用同一区间定义。
- 页面日期选择为空时显示“UTC 滚动 30 天”，选择后显示北京时间自然日；不因时区切换改写历史数据。

## 2026-11-13 CSV 导出专项

- `GET /admin/v2/coupons/export` 的 `ledger`/`redemptions` 在导出前应用同一模板、状态、日期/`days`、门店筛选；一次导出全量结果，不按页面分页截断。
- 文本字段统一经过公式防护：`= + - @` 以及前导空白/制表符/回车/换行后的公式前置 `'`；纯负数、日期、编号和中文保持原值。CSV 使用标准引号转义，允许逗号、双引号、字段内换行。
- `ledger` 的领取时间筛选与券台账一致；`redemptions` 的核销时间按 AuditLog 独立筛选。`start_date/end_date` 使用 `Asia/Shanghai` 自然日 -> UTC 半开区间，缺省 `days` 仍是 UTC 滚动窗口。
- 导出始终脱敏手机号、执行门店权限检查、写 `export_coupon_records` 审计（GET 也会写审计），记录 dataset、筛选、period mode、行数和脱敏模式。
- 自动化只用 CSV 解析验证内容/列数/转义；真实 Excel/WPS 打开及宏/公式执行仍待人工。
