## 业务规则

- 每次生成新海报得到独立的 p. 签名领券码。复制图片、复制链接、重新绘制图片仍是同一张券的领取入口；生成另一张海报才创建新入口。
- 每张海报最多发出 1 张 UserCoupon。匿名只读预览，不占券、不创建顾客；顾客验证手机号登录后，显式点击领取才占用名额。
- 第一位领取者成为券的唯一账户所有者。所有者重复请求或重开链接返回原券及实际状态，不增加券、不延长有效期；其他人仅得到“已被领取”，不返回所有者信息。
- 此规则的限额单位是海报码，不是将同门店所有海报共用为一张券。活动仍沿用已有模板的 100 张总发放上限；打开或生成海报不预扣额度。
- 新券领取后 60 天有效。已使用、过期、锁定券都不能凭该海报再生成新券。
- 核销码由券的账户所有者请求生成，5 分钟有效。店长扫码校验只读；必须现场核对本人账户和券码，再明确确认核销。
- 新海报券的核销请求必须带严格布尔值 holder_present=true。券状态原子从 unused 变为 used，重复或并发核销不能再次消费；所有曾生成的核销码都因券已使用而失效。
- 账户绑定与现场核对不等同于技术上阻止截图转发，不作“无法转发截图”的承诺。

## 接口与存储

- POST /admin/v2/manager/coupons/half-price/poster-link：request_id 为 UUID；按 staff + request_id 幂等，响应 code、poster_id、claimed、expires_at 及活动配额。
- POST /coupons/poster-status：code；可匿名。state 为 available / claimed / unavailable；仅本人登录时返回 owned + 原券信息。
- POST /coupons/claim-half-price：接受 p. 新码；必须顾客登录且账户有手机号。成功返回原券或新券，跨顾客重复返回 409 POSTER_ALREADY_CLAIMED。
- 新码经 guest-claim 入口提交返回 401，不走匿名发券；旧 c. 码及旧匿名券兼容逻辑保留。
- 新增 coupon_poster_links 表，关联门店、模板、创建员工、请求 UUID、到期时间和唯一 coupon_id。无旧表字段修改，无历史数据回填。
- 领取采用 user → template → poster 行锁；生成采用门店 NO KEY UPDATE 锁与模板锁，允许正常外键引用，避免与领取外键检查形成反向等待。
- 领取写券、占用海报码和审计在同一事务提交。签名验证、登录、门店、模板状态、链接到期、额度检查失败均不写券。

## 兼容与预览

- 已经发出的旧公共 c. 活动码仍是旧活动入口，不能追溯改成一张券或作废已领取的权益。正式启用新规则必须换用新生成的海报。
- 历史匿名券继续原读取、绑定及核销流程；本次不迁移其所有人，不回收或删除旧券。
- 顾客领取页按 p. 路由到新流程，其余链接保留旧页面。店长两个发券入口均生成新 p. 海报码。
- 预览版不创建生产海报码、不发送短信、不领用生产券。当前完整交互预览使用合成账户；生产单券二维码需在审查并上线新增表与接口后由店长正常生成。
