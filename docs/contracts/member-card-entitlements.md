## MEMBER-02：受控来源事实更新（2026-10-01）

`POST /admin/v2/membership-cards/{card_id}/facts` 默认 `apply=false` 预览。仅在职本店店长或明确 `store_id` 的总部身份可访问本店卡；异店/未知卡404，员工/技师403，总部未指定门店422。Bearer身份提供核对人，不接受客户端填写操作人。

请求必须给出带时区 `observed_at`、非空 `evidence`、`reason`，以及至少一项 `balance_cents`（整数分、非负、只限储值卡）或 `status=active|disabled`。核对时间必须晚于既有 `recorded_at` 且不在未来；不接收源卡标识、归属、期限、用户资料、钱包或订单字段。已到期卡不能通过恢复操作变成有效卡；停卡、零余额和多卡权益仍由既有域规则判定。

预览返回 `before`、`after`、`version` 和绑定核对人/旧版本/本次内容的 `preview_token`，不写卡或审计。提交须给 `apply=true`、上述版本及预览凭据、8至64字符 `idempotency_key`。服务端锁卡后检查版本，旧版本409；提交内容与预览不同409。请求键作用域为核对人和卡；同键同内容返回原结果且不重复审计，同键不同内容409。审计与卡事实在同一事务提交，审计含人员ID、依据、核对时间、登记时间、前后事实。

本入口只登记有据快照，`balance_realtime=false`；不会形成充值、扣款、赠金或订单改价。客户端金额隐藏约束不变。默认预览的服务器工具为 `scripts.update_member_card_facts`，提交必须读取原预览文件并校验输入文件摘要；流程见 `../operations/member-card-import.md`。导入工具对变化快照整批拒绝的规则继续保留，未建立定时同步或自动失效任务。

## 2026-11-13 脱敏同步回执接入

- `GET /admin/v2/member-sync/receipts` 只读取服务端打包的 allowlist 回执；不遍历私有目录、不读取原始候选、手机号、卡号、余额或凭据。
- 回执索引 `hxy-server/app/content/member_sync_receipts/index.json` 是唯一文件 allowlist；加载时校验每个文件的 SHA-256，索引缺失、字段缺失、摘要不符、格式无效均返回明确错误，不填 0/true。
- 相同 `batch_id` 相同内容幂等去重；相同批次不同内容报告冲突，不覆盖旧回执。SHA 只证明完整性，不单独证明来源真实性。
- `last_success` 与 `latest_attempt` 分开：上次成功提交、最近来源检查/尝试分别展示；当前 `membership_cards` 有效数量不从回执推断，回执也不更新卡。
- 生产回执为 2026-11-06 成功批次 `MEMBER-SYNC-ZHB-20261106-3CARDS`（3卡/3人，备份恢复通过）及 2026-11-13 只读阻塞尝试（116来源卡、15新候选、未提交、业务写入0）；页面显示历史成功与本次待处理，不改成“已同步”。
- 证据引用、SHA 等放在详情；主界面先显示最近成功时间、当前结果和阻塞事项。真实回执来源为服务器私有脱敏摘要，未复制原始输入到 Git 或前端公共目录。

## 2026-11-13 回执冲突、门店与 no_new 修正

- 批次唯一键是 `(store_id, batch_id)`；不同门店的同名批次是独立记录，不互相冲突。
- 同一门店同一批次出现不同事实时，该批次整体失效，不作为 `last_success` 或 `latest_attempt`；不保留第一份、不覆盖、不任意选一份。相同内容重复出现保持幂等。
- 加载结果保留 `conflicts` 供人工核对，但接口只输出本店冲突的批次号/错误码，不输出其他门店的批次、文件名、证据正文或个人信息。
- 先按目标门店选择候选，再计算本店最近成功提交、最近来源核验和最近尝试；无本店回执返回 `no_store_receipt`，不借用其他门店。
- `last_success` 只取 `status=success` 的实际提交；`no_new` 只更新 `last_verification`，不覆盖成功提交时间/批次/新增数。没有成功提交时不得伪造。
- 历史 `blocked` 保留原始运行事实；追加的脱敏状态说明只提供 `current_processing`，不修改旧回执。2026-11-13 原批 116卡/15候选的差异已获授权但用户要求暂缓；授权时间未记录，恢复时仍需重新核验来源与保护基线。
- 当前处理状态只是展示，不是导入授权，也不得因时间经过或回执修复上线自动恢复同步。

## 2026-11-13 回执边界补充

- 状态说明 note 也按 `(store_id, batch_id)` 去重；同批不同 note 时冲突，整批状态说明不可信，不回退选择第一份，也不输出授权/暂停结论。
- 事件排序分别使用自己的时间：
  - 成功提交：`successful_submit_at`
  - 来源核验：`source_verified_at`
  - 尝试：`attempt_at`，缺失才兼容 `source_verified_at`/`successful_submit_at`
- 无时区时间视为未知，不猜测 UTC；未知/非法 JSON、数组、标量、混合时间类型都返回诊断错误，不抛 500。
- 页面提交状态为三态：`true=已提交`、`false=未提交`、缺失/非法=`未记录`；新增数等未知值不显示假零。
