# 管理端媒体资源契约

## 删除引用保护

- 仅总部管理员或当前门店店长可删除所属门店媒体；跨店或不存在媒体统一返回 `404`。
- 删除前，服务端必须检查同店项目主图和详情模块、加项图片、商品图片与页面内容 JSON 中的引用。
- 媒体仍被引用时返回 `409 MEDIA_IN_USE`，只返回引用数量，不返回内容文本或顾客数据；不得调用对象存储删除，也不得写入 `deleted_at`。
- 检查同时识别受控媒体路径和对象键，保证历史签名 CDN 地址仍受保护。
- 未被引用时，先删除对象存储内容；存储删除成功后再将媒体元数据标记为软删除并写入 `media_delete` 审计。存储失败返回错误且不得软删除元数据。

## 既有边界

- 服务端中转上传仅接受 JPG、PNG、WebP、GIF，最大 5MB、2,500 万像素；写入对象存储前必须解码文件、校验实际格式与声明 MIME、文件扩展名一致，拒绝无效或伪造图片。七牛直传的暂存对象在本契约的“七牛直传与断点续传”段落按同一限制复核后才可登记为正式媒体。上传、列表、预览和删除均按门店范围校验。
- 总部上传或查询时必须明确指定目标门店；店长只可操作绑定门店。

## 七牛直传与断点续传

- 当 `MEDIA_STORAGE_BACKEND=qiniu` 时，管理端先调用 `POST /api/v1/admin/media/direct-upload` 获取限时七牛上传凭证、暂存对象键和完成凭证；仅总部管理员或当前门店店长可申请，凭证绑定签发员工、门店、文件名、声明类型、字节数、用途和对象键。未启用七牛的本地环境返回 `409 DIRECT_UPLOAD_UNAVAILABLE`，前端可继续使用既有服务端中转上传。
- 七牛上传策略必须固定到服务端生成的暂存对象键，使用 `insertOnly=1`、5MB `fsizeLimit`、`detectMime=1` 和 JPG/PNG/WebP/GIF `mimeLimit`；浏览器没有 AccessKey、SecretKey 或可自选对象键。
- 前端使用官方 `qiniu-js` 的 `qiniu.upload`，不覆写分片大小、区域或重试配置，遵循 SDK 默认行为。上传中断后“继续上传”复用同一对象键和上传凭证，以便 SDK 使用本地断点信息。
- 上传成功后，前端调用 `POST /api/v1/admin/media/direct-upload/complete`。服务端读取暂存对象并重新校验字节数、实际可解码格式与像素，再移动到正式对象键、创建 `MediaAsset` 并写入审计；同一完成凭证重复调用返回同一媒体记录。无效对象在暂存位置删除，不生成媒体元数据。
- 七牛 Bucket 必须配置仅允许管理后台正式 Origin 的 CORS 上传规则，并为 `stores/*/media/staging/*` 配置生命周期清理。生命周期保留时间应覆盖上传凭证有效期和门店允许的断点重试窗口；未完成暂存对象不应长期保留。
- 病毒扫描本期明确不实现。MIME、扩展名、图片解码和像素限制不是恶意软件扫描；若后续接入扫描服务，必须在本契约补充隔离状态、失败处置、人工放行权限和审计规则。
