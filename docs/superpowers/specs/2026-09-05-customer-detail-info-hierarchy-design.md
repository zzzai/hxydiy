# 顾客端项目详情介绍层级收口设计

此为早期方案 A，已由 `2026-09-05-customer-detail-decision-flow.md` 的最终实施边界替代；不再按本文限制实施范围。

## 目标

让顾客在项目详情首屏依次看懂“这是什么、包含什么、怎么买”，不改变项目标签数据、价格、会员规则、服务位或选购提交契约。

## 现状与问题

现有简介卡同时显示一句项目说明，以及“项目特色、项目简介、选购规则”三组标题和标签。项目简介标签与说明文案存在重复，三层标题在移动端占据首屏高度，选购规则也被埋在同等视觉权重的标签组中。

## 方案 A

### 信息顺序

1. 项目名称与收藏入口。
2. 最多两个项目特色标签，用于回答“这是什么”。按现有 `customerProjectHighlights` 顺序取前两项。
3. 一句项目说明，用于回答“包含什么”。继续使用现有 `customerProjectSummaryText`；项目简介标签不再单独渲染，避免重复。
4. 单行搭配利益点，用于回答“怎么买”。继续使用现有 `customerProjectPurchaseTags`，但只保留对顾客有决策价值的“可自由搭配”表达；不展示“选购规则”标题或“单次服务”等规则化文案。没有可展示内容时不渲染空位。
5. 原有基础价格、会员参考、权益提示和优惠券入口保持原顺序与语义。

### 视觉规则

- 内容面保持纯白；深绿为正文和主信息，浅绿只用于项目特色，暖金只用于“可自由搭配”和价格强调。
- 项目特色使用无组标题的小标签行，最多两枚，防止标签挤占首屏。
- 项目说明为一段自然语言，不转换为标签。
- “可自由搭配”以低高度、单行、弱金色文字呈现，与项目特色区分，但不与价格竞争。
- 标签完整顺序仍遵循“项目特色 → 项目简介 → 选购规则”的数据语义；只是简介由文案承载，规则仅在可转化为“可自由搭配”利益点时呈现。

## 组件与数据边界

- 只修改 `ProjectDetailPage` 的介绍区域及其样式；`LocalDetailPage` 不在本次范围内。
- 不改 `customerProjectHighlights`、`customerProjectSummaryTags`、`customerProjectPurchaseTags` 的来源、标签过滤或业务规则。
- 不改价格计算、会员判断、优惠券、服务位、草稿与提交 payload。

## 无障碍与异常

- 项目特色保留可读的 `aria-label`。
- 搭配利益点使用语义文本，不依赖颜色单独传达“可自由搭配”。
- 说明或规则过长时允许自然换行，不裁切、不水平滚动。
- 无项目特色或可展示的搭配利益点时不显示占位标题、空容器或分隔线。

## 验收与回归

1. 有三类标签的项目：首屏依次显示最多两项特色、说明文本和规则行；不再出现“项目简介”标签组。
2. 规则行保持项目特色之后、价格之前；多条规则以可读分隔符显示。
3. 会员、匿名和非会员价格展示不变化。
4. 390px 移动视口中标题、说明、规则、价格和底部按钮不重叠。
5. 运行顾客端测试、生产构建和 `git diff --check`。

## 非目标

- 不重写整个详情页，不增加折叠、轮播、营销推荐或新标签。
- 不调整菜单、价格、会员权益、项目文案和后端合同。
