# 顾客详情页：按选择过程组织信息

状态：用户已确认方向，并明确要求延续原有二级页 UI；已完成本地实现与验证，未发布。此说明替代原方案 A。

## 最终实施边界

- 常规项目（含小项、套盒）、局部调理、茶饮详情采用同一精简原则，保留原有主图比例、卡片、圆角、配色和按钮。
- 不采用预览图中的整页重排或折叠长图；会员卡属于权益介绍，不改变其业务内容。
- 共用介绍组件对名称／简介中已包含的特色去重；特色最多两项，服务时长、分段规格与套盒次数仍保留。
- 同价合并显示门店价／会员价；不同价继续对比。匿名会员参考价不划线，局部服务保留每部位计价提示。
- 支持真实加购的区域展示“可自由搭配”，不支持加购的项目不显示该提示。

## 所属工作

- 产品：交易型产品的用户体验设计，包含信息架构、交互设计、内容设计与价格信息呈现。
- 内容运营：维护项目名称、服务包含项、时长、图片及必要说明的准确性与一致性。
- 用户运营：制定拉新、会员转化、复购和促销规则；本轮用户明确暂停新增发券。
- 数据分析：验证顾客能否理解金额并完成选择，不只考核页面点击或加购金额。

## 场景假设

顾客已到店并扫码，需要尽快看懂项目、确认金额、表达服务偏好并提交。该假设来自产品场景，尚需现场观察验证，不把它写成已完成的用户研究结论。

## 布局

1. 顶栏：返回、项目详情、当前服务位。
2. 主图：延续现有比例与风格；通过压缩重复介绍让价格提前，不裁切图片。
3. 项目介绍卡：项目名 → 一句服务包含项／必要时长 → 基础门店价与会员参考。特色只保留未被名称和介绍表达的重要差异，不强制凑两枚标签。
4. 服务偏好：清楚标注包含、不加价与必选情况；沿用既有业务默认值，选中状态可识别。
5. 自由搭配：在真实支持加购的区域使用“可自由搭配”，收费服务标明增量价格，避免暗示免费或任意组合。保留主项目、小项和局部加强层级。
6. 图文详情：为需要进一步了解的顾客提供完整图片与说明，长图按原始比例显示。
7. 固定底栏：本次预计合计与明确的加入／保存按钮；金额随当前选择更新，明细可查看，提交后能继续选购。

## 内容收简

- 不显示“项目特色”“项目简介”“选购规则”等元信息标题，不重复“价格透明”“单次服务”。
- 不显示匿名领券卡或送券登录引导。
- 同价时可合并门店价与会员价标签；有差价时保留两价对比。此项属于待实施的价格展示优化，需回归验证，不修改计算规则。
- 不因为文案收简删掉真实适用限制、服务范围或额外费用说明。
- 当前截图中的静态爱心未绑定收藏交互；后续布局实现应移除该装饰，避免顾客以为可以点击收藏。

## 心理与验证

先回答顾客当下的问题，后展示下一步可选内容，减少重复阅读和记忆负担。依据：
- NN/g 商品详情页研究：https://www.nngroup.com/articles/ecommerce-product-pages/
- NN/g 渐进呈现：https://www.nngroup.com/articles/progressive-disclosure/

验证重点：顾客能否说清服务包含项、基础价与加购后总价；能否区分免费偏好与收费加购；能否独立完成加入、修改、提交与继续选择。关注提交完成率、价格相关返回修改、求助与误选；停留时长仅作辅助，不直接等同体验好坏。
