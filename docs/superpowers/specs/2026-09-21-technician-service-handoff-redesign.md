# 技师服务交接重设计

日期：2026-09-21

## 目标

技师结束服务后，用 20–40 秒留下下一次服务会实际用到的信息；下一位技师在 10 秒内读懂。界面不再展示一组泛化画像标签，也不暴露内部英文编号。

## 范围

本次同时完成三项改动：

1. 服务后记录重做为“交接预览＋少量点选”；
2. 服务单只显示服务位、项目和中文状态，不显示 `position-*`、数据库 ID 或 `#` 编号；
3. 会员核验先扫码，再匹配待核验服务单；打开摄像头不依赖预先选择位置。

不改价格规则、服务位状态机、排班、派单、结算和智慧宝物理控制。

## 服务后交接

### 默认顺序

1. 顶部实时生成一句交接，例如：“下次先问力度，肩颈轻一些，顾客想安静休息。”
2. 服务方式：安静休息、轻松聊天。
3. 本次重点部位：肩颈、腰背、腿部、膝盖、足部；每个部位必须同时选择下次动作：重点加强、轻一些、避开、先确认。最多三处。
4. 其他关键变化：温度低些、温度高些、节奏慢些、提前结束等，按服务项目裁剪。
5. 顾客基本信息首次补充：年龄段和性别，均为顾客自述、可不选择。界面不显示“不记录”按钮。
6. 按需补充身体情况和仅本人可见备注，默认收起。
7. 顾客确认复选框；未确认仍可保存，但不能成为跨技师确认事实。
8. 固定底部提供“本次无新情况”和“保存并完成”。

年龄稳定编码与中文展示：

| 编码 | 展示 |
| --- | --- |
| `age_25_29` | 25–29 |
| `age_30_34` | 30–34 |
| `age_35_39` | 35–39 |
| `age_40_44` | 40–44 |
| `age_45_49` | 45–49 |
| `age_50_59` | 50–59 |
| `age_60_plus` | 60以上 |

性别稳定编码仅有 `male`（男）和 `female`（女）。未选择字段即不写入，不增加第三种展示选项。

### 数据契约

新写入使用 `schema_version=7`、`taxonomy_version=service_handoff_v1`。v1–v6 保持只读兼容。新结构只保存：

- `communication`：服务沟通方式；
- `body_focus[]`：`region + next_action`；
- `session_changes[]`：本次实际变化；
- `basic_info`：可选年龄段与性别；
- `private_note`：仅创建技师本人可见；
- `recording_outcome=no_additional_notes`：本次无新情况。

内部保存英文稳定编码，所有技师端可见内容使用中文。自由文字不得进入跨技师摘要。年龄、性别、身体部位不得自动写入普通运营标签、营销分群或差别定价。

## 历史和更正

- 本人历史继续显示旧记录，新 v7 使用新的中文交接摘要。
- 本人可对自己的 v7 记录追加一次带原因的更正，原记录保留。
- 服务前参考只返回顾客确认过的白名单字段；身体部位仍提示当次再次确认。
- 管理端不获得私人备注；身体记录仍降级为“服务前再确认”。

## 会员核验

1. 页面首屏直接提供“打开摄像头扫码”。
2. 扫码成功后显示脱敏会员信息，并加载本店可核验服务单。
3. 只有一个候选时自动选中；多个候选时由员工按中文服务位、项目数和提交时间选择。
4. 选择后才点击“确认核验本次服务单”。
5. 继续沿用动态码锁定、门店隔离、幂等、会员价原子重算和审计。

## 错误与弱网

- 保存中禁用重复提交；相同载荷复用幂等键，内容变化后换新键。
- 保存失败保留全部选择并显示“重试保存”。
- 会员扫码失败可重新扫码；扫码成功但候选加载失败时保留已扫码状态并允许重试加载。
- 关闭未保存交接时明确提示继续填写或放弃。

## 验收

- 技师能不输入文字完成一次有效交接。
- 服务单界面不出现英文内部编码或 `#` 编号。
- 会员扫码前不要求选择服务位置。
- 新 v7 的权限、门店隔离、服务状态、幂等、审计和更正约束通过合同测试。
- 前端移动端无横向溢出，主要操作可单手完成。
