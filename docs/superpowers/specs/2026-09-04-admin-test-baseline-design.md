# 管理后台全量测试基线收口设计

日期：2026-09-04

## 目标

让后端全量测试重新反映当前真实业务与发布代码，消除已确认的过期测试失败，不改变生产登录权限、业务流程或部署行为。

## 业务边界

- 现有 `staff` 数据均为测试账号，不迁移、不兼容，也不恢复登录能力。
- 正式账号只使用当前规范角色：总部 `admin`、店长 `manager`、已绑定技师档案的 `technician`。
- 本任务不新增普通员工角色，不修改顾客端、技师端业务或智慧宝逻辑。

## 修改范围

1. 将仍依赖旧 `staff` 登录语义的测试夹具改为与测试行为匹配的规范角色。
2. 让 Alembic 测试夹具准确模拟目标迁移之前的数据库，并将迁移头断言对齐当前实际唯一 head。
3. 逐项核对发布测试：过期断言对齐当前受支持的 release/current 部署方式；仅测试引用、但仓库不再提供的临时工具不恢复为生产依赖。
4. 不通过放宽认证、回退迁移或改变现行部署配置来迎合旧测试。

## 验证

- 先逐项复现每类失败并确认根因。
- 修改测试后运行相关专项测试。
- 最后运行后端全量测试，确认没有新增失败。
- 执行 `git diff --check` 并检查变更只涉及测试与必要说明文档。

## 完成标准

- 当前 11 个失败均被正确校正或以仍然真实的缺陷单独保留。
- 生产代码行为不变。
- 结果提交、推送并通过 GitHub 实际检查后合入 `main`。
