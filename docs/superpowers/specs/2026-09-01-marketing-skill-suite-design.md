# 营销内容 Skill 套件设计

日期：2026-09-01

## 目标

将广告内容生产拆为可独立调用、可串联交付的九个本地 Skill。套件用于从消费者信息到渠道内容和复盘指标的营销工作，不代替事实研究、法务审核、投放执行或外部发布。

## 架构

`marketing-orchestrator` 是总控入口，只在用户要求完整活动、整套传播方案或端到端营销执行时触发。它检查输入完整度，按需串联专项 Skill，并输出一份可审阅的活动包。

专项 Skill 保持独立，用户可单独调用其中任意一个：

| Skill | 职责 | 主要交付物 |
| --- | --- | --- |
| `customer-research` | 整理已有访谈、评价、评论、问卷或公开研究 | 洞察、证据、痛点和待验证假设 |
| `marketing-psychology` | 将洞察转成合规的动机与表达策略 | 行为动机、阻力、信息框架 |
| `brand-positioning` | 界定目标受众、差异化与品牌语气 | 定位陈述、信息支柱、禁用表达 |
| `content-strategy` | 规划内容主题、渠道优先级和节奏 | 内容支柱、选题池、内容日历 |
| `ad-creative` | 扩展广告切角和可测试创意组合 | 创意方向、钩子、素材要求、测试矩阵 |
| `copywriting` | 产出广告标题、正文、CTA 和落地页文案 | 按渠道分组的文案版本 |
| `social-content` | 将核心创意适配小红书、抖音、微信、LinkedIn 等渠道 | 各渠道正文、形式建议和发布要点 |
| `campaign-analytics` | 定义指标、分析真实数据并提出下一轮假设 | 指标树、实验复盘、行动建议 |
| `marketing-orchestrator` | 选择和编排上述能力 | 完整活动包与假设/待确认清单 |

## 编排规则

默认路径为：

`customer-research → marketing-psychology → brand-positioning → content-strategy → ad-creative → copywriting → social-content → campaign-analytics`

这不是强制链路。已有品牌定位时跳过定位；只要短视频脚本时直接使用 `social-content`；仅需要广告标题时直接使用 `copywriting`。总控必须说明跳过了哪些环节及原因。

## 输入与交接

每个 Skill 首先提取或询问完成当前任务最低限度的信息：产品/服务、目标、受众、渠道、地区与语言、预算或资源限制、上线时间、已有证据和合规限制。信息不足时，输出带假设的草案，并将假设与待确认事项分开列示。

上游交接必须保留：

- 证据来源或“仅为假设”的明确标记；
- 目标受众与排除受众；
- 核心主张、可证实依据和禁止夸大项；
- 渠道、格式、CTA 和衡量指标；
- 未解决风险和需要人工批准的事项。

## 质量与安全边界

- 不编造消费者访谈、评价、市场数据、产品能力或效果承诺。
- 将观察结果、推断和建议清楚区分；没有数据时不伪装为验证结论。
- 不根据敏感个人特征进行歧视性定向，也不使用操纵、恐吓、虚假稀缺或无法证实的承诺。
- 涉及医疗、金融、未成年人、法律、烟酒或其他受监管行业时，提示用户安排领域审核，不替代合规、法务或平台审核。
- Skill 可以生成草案和发布建议；实际投放、公开发布、修改广告账户或传输敏感受众数据前，必须取得用户当次明确授权。

## 文件与发现方式

Skill 安装在 `C:\Users\gaoji\.codex\skills\`，每项使用独立目录和 `SKILL.md`。默认允许自动发现；不创建脚本、资产或第三方连接器，因为当前任务只需指导工作流，不需要可执行自动化。

## 验证

每个目录运行 `quick_validate.py`。再以两类请求作人工路由检查：

1. “为新品做完整小红书和抖音推广方案”应由 `marketing-orchestrator` 统筹。
2. “把这段卖点改成 3 条微信朋友圈文案”应直接进入 `copywriting` 或 `social-content`，不强制完整链路。
