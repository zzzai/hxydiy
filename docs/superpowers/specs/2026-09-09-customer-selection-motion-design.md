# 顾客端选购闭环动效设计

状态：待用户审阅  
范围：顾客端 H5 的项目列表顶部权益区、分类导航、项目详情、底部选购栏和选购清单
日期：2026-09-09

## 目标

用克制、可预期的反馈让顾客确认“我现在能得到什么、已打开、已加入、金额已更新、已提交”，提升选购闭环的节奏感，但不改变价格、选单、服务位、身份或提交接口。

## 不在本次范围

- 不使用轮播惯性、卡片倾斜、长按预览或隐藏手势。
- 不改变项目内容、图像比例、价格文案、优惠规则或服务状态机。
- 不为动效新增接口、埋点字段或浏览器持久化数据。

## 交互方案

### 0. 菜单页顶部权益区（A：克制高级）

- 菜单页常态采用“一张主权益卡 + 下一张轻露出”的横向滑动布局；主卡承载当前身份真正适用的一条权益，下一张只作为可继续横滑的视觉提示。
- 保留项目列表原有的左侧一级分类导航。顶部权益区只承担权益理解与横滑提示，不能替代或挤压“泡脚、调理、采耳”等分类定位路径。
- 主卡使用深绿色、低对比装饰与明确的权益标题；次卡使用浅绿色。卡片高度、圆角和间距保持稳定，避免轮播、自动播放、倾斜或夸张缩放。
- 只展示当前顾客身份、门店和活动状态下真实适用的信息；匿名顾客不展示已停止的送券策略，活动失效或内容为空时整个权益区应收起，不留占位。
- 横滑不使用惯性翻页计算；手指拖动结束后自然停稳。使用低调的进度点与下一张露出边缘告知“可继续看”，不使用箭头催促或整卡闪动。
- 用户横滑后，不把卡片位置写入订单、服务状态或价格缓存；刷新回到后端和当前身份决定的首张有效权益。

### 1. 项目卡打开详情（POP）

- 点击项目卡后，详情层从卡片方向轻推并淡入；退出时反向淡出并回退。
- 使用 180ms 的 ease-out 位移与透明度，不动画宽高、页面布局或长图尺寸。
- 原有点击、键盘 Enter/Space、关闭和浏览器返回语义不变。

### 2. 加入本次服务（COMMIT）

- 详情页“加入本次服务”按钮仅提供按压反馈；现有保存动作完成后会关闭详情层，因此不在已卸载按钮上伪造“已加入”结果。
- 同一动作在真实选单状态已更新后带动底部选购栏出现或数量更新，并沿用现有成功提示；金额与数量只做短距离淡入/上移替换，不让整块底栏跳动。
- 正在保存、接口失败或只读状态仍以既有文案和禁用规则为准；动效不得伪造配置已保存或提交成功。

### 3. 查看选购（SHEET）

- 选购清单仍从底部打开，顺序为：标题与关闭按钮 → 服务位/身份 → 明细 → 金额区，间隔 80–120ms。
- 抽屉保持现有“少项内容自适应、多项明细滚动”的尺寸规则；不在动效中修改高度。
- 关闭时整体短距离回落淡出；背景遮罩与焦点管理沿用现有实现。

### 4. 金额、数量与提交状态（TEXT）

- 金额、已选数量和“正在更新/预计合计”等状态采用 key 驱动的淡入替换，位移不超过 6px。
- 金额真实值仍由现有报价计算决定；无价格变化时不触发动效。
- 提交结果仍用当前成功页；本期不重做为复杂的全宽结果条。

## 技术边界

- 复用 `diy-web/src/motionPresets.ts` 和 Framer Motion，不引入新依赖。
- 新增统一的动效 transition：150–240ms、`ease-out` 或轻微 spring；所有退出动画可被关闭、返回、异常状态中断。
- 使用 `useReducedMotion()`：系统设置减少动态效果时只保留短淡入淡出，取消位移、缩放和错峰。
- 只动画 `opacity`、`transform`；不得动画高度、宽度、top/left、filter 或大面积 box-shadow。
- 低端设备、弱网和请求失败必须保持同一最终状态与可点击性；动画不等待网络，也不阻塞提交。

## 组件职责

| 位置 | 职责 |
| --- | --- |
| `motionPresets.ts` | 提供详情、提交反馈、抽屉与数字替换的共享预设及减少动态效果降级。 |
| `App.tsx` | 为顶部权益区、底部选购栏数量/金额变化提供稳定 key 和完成态，不改变草稿或报价计算。 |
| `ProjectDetailPage.tsx`、`LocalDetailPage.tsx`、`TeaDetailPage.tsx` | 复用详情进入/退出预设与加入完成态展示。 |
| `SelectionSummarySheet.tsx` | 保持现有抽屉行为，仅为四个静态区域添加错峰进场。 |

## 验收与回归

1. 顶部权益区仅在存在真实适用内容时显示；左侧分类导航仍可见、可滚动且不被卡片遮挡。
2. 权益区横滑可被触摸、鼠标和键盘操作；不会自动轮播，不影响首次进入项目列表或分类切换。
3. 项目卡打开/关闭详情时不产生布局动画，键盘操作与返回行为不变。
4. 配置保存后，底部选购栏的数量或金额变化有反馈；失败或只读时不显示“已加入”。
5. 少项清单没有固定高度留白；多项清单只滚动明细，金额区与提交按钮可见。
6. 启用 `prefers-reduced-motion` 时无位移、缩放和错峰，操作和内容仍完整可用。
7. 回归覆盖权益区展示条件、分类导航、动效预设、抽屉结构、选单数量/价格和无障碍标记；全量顾客端测试、生产构建和 `git diff --check` 通过。

## 发布与现场验证

- 本次不涉及数据库迁移、API、价格或跨端契约。
- 发布后以匿名、非会员、会员三种身份核验：顶部权益展示条件、分类切换、打开详情、加入、查看选购、修改数量和提交。
- 自动化验证不替代真实门店的触控、弱网和减少动态效果现场验收。
