# 顾客端选购闭环动效设计

状态：待用户审阅  
范围：顾客端 H5 的项目列表、项目详情、底部选购栏和选购清单  
日期：2026-09-09

## 目标

用克制、可预期的反馈让顾客确认“已打开、已加入、金额已更新、已提交”，提升选购闭环的节奏感，但不改变价格、选单、服务位、身份或提交接口。

## 不在本次范围

- 不使用轮播惯性、卡片倾斜、长按预览或隐藏手势。
- 不改变项目内容、图像比例、价格文案、优惠规则或服务状态机。
- 不为动效新增接口、埋点字段或浏览器持久化数据。

## 交互方案

### 1. 项目卡打开详情（POP）

- 点击项目卡后，详情层从卡片方向轻推并淡入；退出时反向淡出并回退。
- 使用 180ms 的 ease-out 位移与透明度，不动画宽高、页面布局或长图尺寸。
- 原有点击、键盘 Enter/Space、关闭和浏览器返回语义不变。

### 2. 加入本次服务（COMMIT）

- 详情页“加入本次服务”按钮在确认成功时进入短暂的完成态：按压反馈后显示已加入，再恢复可继续编辑的正常按钮。
- 同一动作带动底部选购栏出现或数量更新；金额与数量只做短距离淡入/上移替换，不让整块底栏跳动。
- 正在保存、接口失败或只读状态仍以既有文案和禁用规则为准；动效不得伪造提交成功。

### 3. 查看选购（SHEET）

- 选购清单仍从底部打开，顺序为：标题与关闭按钮 → 服务位/身份 → 明细 → 金额区，间隔 80–120ms。
- 抽屉保持现有“少项内容自适应、多项明细滚动”的尺寸规则；不在动效中修改高度。
- 关闭时整体短距离回落淡出；背景遮罩与焦点管理沿用现有实现。

### 4. 金额、数量与提交状态（TEXT）

- 金额、已选数量和“正在更新/预计合计”等状态采用 key 驱动的淡入替换，位移不超过 6px。
- 金额真实值仍由现有报价计算决定；无价格变化时不触发动效。
- 提交结果仍用当前成功页；本期不重做为复杂的全宽结果条。

## 技术边界

- 复用 `diy-web/src/motionPresets.ts` 和 Framer Motion，不引入新依赖。
- 新增统一的动效 transition：150–240ms、`ease-out` 或轻微 spring；所有退出动画可被关闭、返回、异常状态中断。
- 使用 `useReducedMotion()`：系统设置减少动态效果时只保留短淡入淡出，取消位移、缩放和错峰。
- 只动画 `opacity`、`transform`；不得动画高度、宽度、top/left、filter 或大面积 box-shadow。
- 低端设备、弱网和请求失败必须保持同一最终状态与可点击性；动画不等待网络，也不阻塞提交。

## 组件职责

| 位置 | 职责 |
| --- | --- |
| `motionPresets.ts` | 提供详情、提交反馈、抽屉与数字替换的共享预设及减少动态效果降级。 |
| `App.tsx` | 为底部选购栏数量/金额变化提供稳定 key 和完成态，不改变草稿或报价计算。 |
| `ProjectDetailPage.tsx`、`LocalDetailPage.tsx`、`TeaDetailPage.tsx` | 复用详情进入/退出预设与加入完成态展示。 |
| `SelectionSummarySheet.tsx` | 保持现有抽屉行为，仅为四个静态区域添加错峰进场。 |

## 验收与回归

1. 项目卡打开/关闭详情时不产生布局动画，键盘操作与返回行为不变。
2. 加入成功后，底部选购栏的数量或金额变化有反馈；失败时不显示“已加入”。
3. 少项清单没有固定高度留白；多项清单只滚动明细，金额区与提交按钮可见。
4. 启用 `prefers-reduced-motion` 时无位移、缩放和错峰，操作和内容仍完整可用。
5. 回归覆盖动效预设、抽屉结构、选单数量/价格和无障碍标记；全量顾客端测试、生产构建和 `git diff --check` 通过。

## 发布与现场验证

- 本次不涉及数据库迁移、API、价格或跨端契约。
- 发布后以匿名、非会员、会员三种身份核验：打开详情、加入、查看选购、修改数量和提交。
- 自动化验证不替代真实门店的触控、弱网和减少动态效果现场验收。
