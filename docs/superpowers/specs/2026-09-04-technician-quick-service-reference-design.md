# 技师快速服务参考与下次摘要设计

## 目标

把服务结束后的顾客画像记录改成 20～30 秒可完成的“服务参考快记”，并在顾客下次到店、存在当前活动服务位时，向同店在岗技师展示最近一次经顾客确认的安全摘要。

本功能记录的是服务偏好和当次反馈，不建立医疗档案，不推断消费能力、性格或健康结论。

## 范围

### 本轮实现

- 用点选式快速记录替换技师端原有的年龄、性别、体型和职业录入。
- 记录本次重点、避开/谨慎部位、力度、温度、服务反馈、下次建议、顾客确认和可选顾客原话。
- 在当前活动服务单中提供“查看上次服务参考”。
- 只展示最近一次“已与顾客确认”的安全字段。
- 保留现有门店隔离、本人完成服务约束、幂等、审计、失败重试和非医疗用语校验。

### 本轮不做

- 不使用 AI 推断画像。
- 本轮不自动合并多次记录，不计算置信度或顾客分层；但数据结构必须支持未来离线计算。
- 不展示消费金额、完整历史备注、手机号或人口属性。
- 不增加录音、语音转写、医疗信息或自由创建标签。
- 不改变派单、接单、智慧宝现场控制和结算边界。

## 交互设计

### 服务结束后的快速记录

服务结束后沿用底部抽屉，标题改为“本次服务参考”。表单按操作顺序展示：

1. **本次重点**：肩颈、腰臀、腿部、腹部、足部、整体放松；多选。
2. **避开或谨慎**：肩颈、腰臀、腿部、腹部、足部；多选，可不填。
3. **力度偏好**：轻柔、适中、偏强；单选，可不填。
4. **温度偏好**：偏低、适中、偏高；单选，可不填。
5. **服务反馈**：本次合适、调整后更合适、下次需调整；单选，可不填。
6. **下次建议**：延续本次、到店再确认；单选，可不填。
7. **已与顾客确认**：开关，默认关闭。只有技师确实向顾客复述并得到确认后才能打开。
8. **顾客原话**：最多 100 字，可选；提示“只记服务偏好，不记诊断或隐私信息”。

底部保留“暂不记录”和“保存服务参考”。至少选择一项或填写顾客原话才能保存。保存中禁用关闭和重复提交；失败后使用同一幂等键重试。

表单不再要求技师判断年龄、性别、体型和职业。记录来源由字段语义表达：顾客原话和确认状态属于顾客表达，其余属于本次服务观察与现场沟通；API 记录来源使用 `both`（已确认）或 `service_observation`（未确认）。

### 下次服务前摘要

活动服务单存在顾客 ID 时显示“查看上次服务参考”。点击后请求受限接口并记录查看审计。

摘要只展示最近一次界面标记为“已与顾客确认”、数据字段为 `customer_confirmed=true` 的记录：

> 上次已确认服务参考  
> 重点：肩颈、腿部  
> 避开：腹部  
> 力度：适中 · 温度：偏低  
> 反馈：调整后更合适  
> 下次：延续本次  
> 2026-09-04 · 请本次服务前再次确认

没有已确认记录时显示“暂无顾客确认的历史服务参考，请现场询问”。不回退展示未确认观察，不展示自由备注或顾客原话。

## 数据与接口

### 从当前建立可扩展的数据底座

前端继续保持简单，但存储不能使用中文展示文案或逗号拼接字符串。`customer_profile_records.profile` 保存版本化 JSON：

```json
{
  "schema_version": 2,
  "taxonomy_version": "service_reference_v1",
  "customer_reported": {
    "focus_areas": ["neck_shoulder", "legs"],
    "avoid_areas": ["abdomen"],
    "force_preference": "medium",
    "temperature_preference": "lower",
    "quote": "肩颈可以重点按，热敷不要太热"
  },
  "technician_observed": {
    "service_feedback": "better_after_adjustment"
  },
  "next_visit": {
    "plan": "repeat_current"
  }
}
```

界面使用中文，API 和数据库保存稳定编码。编码一经发布不得改变语义；需要调整时发布新的 `taxonomy_version`，不能把旧编码改成新含义。

稳定编码如下：

- 部位：`neck_shoulder`、`waist_hip`、`legs`、`abdomen`、`feet`、`full_relaxation`。
- 力度：`gentle`、`medium`、`strong`。
- 温度：`lower`、`medium`、`higher`。
- 反馈：`suitable`、`better_after_adjustment`、`adjust_next_time`。
- 下次建议：`repeat_current`、`confirm_on_arrival`。

数组按用户选择顺序去重保存，空数组表示“本次明确没有选择”，字段不存在表示“未采集”，两者不得混用。自由文本只作服务上下文，不作为自动标签或算法事实。

### 关系字段与索引

对 `customer_profile_records` 做一次小型迁移，增加：

- `schema_version`：整数，旧记录默认 `1`，新快记写入 `2`。
- `taxonomy_version`：字符串，新快记写入 `service_reference_v1`。
- `customer_confirmed`：布尔值，默认 `false`。
- `confirmed_at`：顾客确认时写入服务端时间，否则为空。

保留现有 `store_id`、`user_id`、`selection_session_id`、`technician_id`、`created_by_staff_id`、`source`、`created_at`、`correction_of_id` 和幂等键。新增复合索引：

- `(store_id, user_id, customer_confirmed, created_at DESC)`：读取顾客最近一次已确认摘要。
- `(store_id, technician_id, created_at DESC)`：门店和技师维度的离线分析抽取。
- `selection_session_id` 保持索引和服务关联校验；同一服务的更正通过新记录追加版本。

每次服务追加一条不可覆盖的事实记录。更正通过 `correction_of_id` 追加，不修改原记录；这样未来可以还原当时事实、分析纠正率并排除被更正版本。

### 多门店和大量顾客场景

- 所有在线查询必须首先按 `store_id` 收窄，不能扫描全链路顾客记录。
- 顾客摘要在线读取只查复合索引和最近一条记录，不在请求内聚合全部历史。
- 总部跨门店分析不得直接在生产事务库执行大范围 JSON 查询。未来通过 CDC 或增量 ETL 按记录 ID/创建时间同步到分析库。
- 分析库使用内部匿名顾客键，不导出手机号、昵称、顾客原话或自由备注。
- `store_id`、项目 ID、技师 ID、服务时间和标准编码作为分析维度；展示名称可变，不能作为统计主键。
- 门店自定义标签不自动进入连锁统一口径。只有总部发布到统一字典并带版本号后，才可参与跨门店比较。

### 数据的长期价值

在不增加当前录入负担的前提下，这组数据未来可支持：

- **顾客服务连续性**：下次服务快速恢复已确认的力度、温度、重点和避开部位。
- **门店运营**：分析顾客最常提出的重点、调整原因和“下次需调整”比例，用于培训和服务流程改进。
- **连锁经营**：使用统一编码比较不同门店、项目和时段的偏好分布，不依赖各店自由文案。
- **产品优化**：识别项目配置与真实服务调整之间的差异，优化项目说明、时长和标准手法。
- **未来推荐**：以顾客确认、记录新鲜度、重复出现次数和服务反馈作为特征；未经确认的单次观察不能直接成为推荐结论。

这些用途是数据结构的兼容目标，不代表本轮建设数据仓库、报表、推荐模型或顾客分层。

### 数据治理

- “已与顾客确认”只表示顾客确认本次服务偏好，不等同于营销授权或敏感信息处理同意。
- 自由文本禁止诊断、疾病、治疗结论、联系方式、消费能力和人格评价。
- 运营库保留原始事实与审计；未来分析侧默认不复制顾客原话和备注。
- 总部汇总只展示达到最小样本量的聚合结果，避免通过小样本反推出具体顾客或技师。
- 后续新增字段必须明确业务用途、编码字典、来源、空值含义、保留期限和访问角色。

后端逐字段校验 JSON 结构、版本、固定编码、数组去重、字符长度和医疗禁词。旧版画像继续可读，避免破坏历史记录，但技师新表单不再提交旧人口属性。

### 受限摘要接口

新增：

`GET /api/v1/technician/occupancies/{occupancy_id}/service-reference`

约束：

- 登录账号必须是状态正常且绑定技师档案的同店技师。
- 占用必须属于同一门店，且 `active_room_id`、`active_session_id` 仍有效。
- 当前选单必须关联顾客。
- 只查询该顾客最近一次 `customer_confirmed=true` 且未被后续更正替代的记录。
- 响应仅包含受控摘要字段、记录日期和固定提示，不返回备注、顾客原话、创建人或其他画像字段。
- 每次成功查看写入 `technician_view_service_reference` 审计，关联占用、顾客、技师和来源记录 ID。

由于当前产品明确不做派单，待服务阶段无法绑定唯一技师。因此权限按“同店、在岗技师、当前活动服务位、显式点击查看”控制；服务位释放后立即不可读取。

## 错误与空状态

- 无当前活动占用：返回 `409 SERVICE_REFERENCE_UNAVAILABLE`。
- 跨门店或占用不存在：返回 `404`，不泄露资源存在性。
- 选单未关联顾客：返回空摘要，不创建审计。
- 没有已确认记录：返回 `record: null` 和固定空状态文案。
- 保存内容全部为空：返回 `422`。
- 枚举、长度或非医疗边界不合法：返回 `422`，前端保留已填内容。
- 网络失败：前端展示“保存失败，请检查网络后重试”，使用原幂等键重试。

## 测试与验收

### 后端

- 接受完整的 `schema_version=2` 结构并拒绝未知字段、未知编码、重复数组值、超长原话和医疗诊断词。
- 旧版记录保持兼容；新旧版本的空值语义不会混淆。
- 技师只能写入本人完成服务的记录。
- 同一幂等键同内容重放成功，不同内容返回冲突。
- 摘要只返回最近一次已确认记录。
- 未确认记录、备注、原话和旧人口属性不会出现在摘要。
- 跨店、已释放服务位、无效技师账号不能读取。
- 成功读取写入审计；空摘要不写审计。

### 前端

- 快记表单不再出现年龄、性别、体型和职业。
- 所有主要字段可通过点选完成，顾客确认默认关闭。
- 空表单不能提交，顾客原话限制 100 字。
- 已确认与未确认分别提交 `both` 和 `service_observation`。
- 保存失败保持表单内容并复用幂等键。
- 服务单可打开摘要；空摘要、加载失败和有效摘要均有明确状态。
- 390×844 视口中，主要字段和底部操作不互相遮挡，触控按钮高度不少于 40px。

### 生产验收

- 使用授权测试服务位和 `tech-1` 完成一次已确认记录。
- 释放服务位后验证摘要接口不可读取。
- 新测试选单进入活动服务位后验证摘要可见且不含备注、原话或人口属性。
- 核对写入、查看审计和幂等重试；清理脱敏测试画像并释放测试位。
- 核对新增复合索引被最近摘要查询使用，避免顾客量增长后退化为全表扫描。

## 成功标准

- 熟悉流程的技师可在 30 秒内完成一次有效记录。
- 无需键盘也能完成除顾客原话外的全部记录。
- 下次服务只展示经顾客确认、与当前服务直接相关的安全摘要。
- 不扩大技师对顾客历史数据的常驻访问权限。
- 新记录使用稳定编码、数组、版本号和明确空值语义，可被未来增量同步到分析库而无需清洗中文文案或拆分字符串。
