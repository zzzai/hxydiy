# 技师移动端工作台设计

日期：2026-08-26  
状态：待用户审阅

## 1. 背景与目标

当前技师角色被放在门店管理后台中，虽然可以在桌面浏览器访问，但不符合技师在服务现场使用手机完成任务的场景。本项目将技师端调整为手机优先的独立移动 Web，桌面端技师登录和后台导航不再作为正式入口。

目标：

- 技师打开独立地址即可登录并进入自己的工作台。
- 在单手操作和小屏幕下完成查看任务、确认服务、服务结束和顾客服务参考快记。
- 复用现有 Staff/Technician 账号模型、技师 API、门店隔离、权限校验、幂等和审计能力。
- 不承接智慧宝负责的开房、派钟、离位、清洁和物理资源释放。

非目标：

- 不开发原生 App 或小程序。
- 不在技师端提供经营分析、房间管理、派钟、清洁、薪资和全店顾客查询。
- 不改变服务单、服务位和智慧宝履约单的职责边界。

## 2. 入口与信息架构

正式入口：`https://diy.hexiaoyue.com/technician/`

页面：

- `/technician/login`：技师账号登录；登录成功后进入 `/technician/today`。
- `/technician/today`：今日服务，按待确认、服务中、已完成分组。
- `/technician/history`：本人已完成服务记录，仅展示完成工作所需的最小信息。
- `/technician/me`：本人资料、门店、等级、账号状态、请假/离职状态和退出登录。

移动端采用底部三栏导航：今日服务、服务记录、我的。页面不显示桌面管理后台侧栏，不向技师暴露其他后台路由。

## 3. 核心交互

### 3.1 今日服务

- 顶部显示门店、技师姓名和当前日期。
- 服务卡片显示房间/服务位、服务项目、顾客选单必要摘要和当前状态。
- `waiting_service` 状态显示主按钮“确认服务”。
- `in_service` 状态显示主按钮“服务结束”。
- `post_service_present` 状态显示“填写服务参考”，引导完成快记。
- 无任务时显示明确空状态和下拉刷新/刷新按钮。
- 所有动作提交期间按钮禁用并显示进度，成功后刷新任务状态；重复提交使用幂等键。

### 3.2 服务参考快记

- 仅在服务结束且当前技师确实关联该服务时可进入。
- 使用可点选标签和自由输入，字段文案采用“顾客自述”“服务观察”“服务注意事项”。
- 禁止医疗诊断式表述；不允许记录诊断、治疗结论或无关敏感信息。
- 保存成功后显示确认状态，并可返回今日服务。

### 3.3 我的

- 展示 Staff 登录身份与关联 Technician 档案，不合并两个对象。
- 展示账号状态：在岗、忙碌、停用、离职等只读状态。
- 提供退出登录；请假能力沿用现有服务端流程，若移动端首期不提供入口则保持 API 可用。

## 4. 技术方案

- 在现有前端工程中新增独立移动端入口/路由壳，移动端组件与管理后台布局解耦。
- 复用现有 `/technician/me`、`/technician/tasks`、确认服务、服务结束和画像记录 API。
- 前端路由守卫仅允许 `technician` 角色访问移动技师路由；管理员/店员访问时跳转到管理端或无权限页。
- API 继续执行服务端角色校验、门店范围校验、本人技师关联校验和审计写入；前端不承担安全边界。
- 首期采用响应式移动 Web，保证 320px 至 430px 视口可用；桌面视口只提供窄屏居中预览，不恢复桌面后台式布局。
- 登录态沿用现有 token 机制，增加移动端过期处理和重新登录提示。

## 5. 数据流与错误处理

1. 登录成功后获取当前 Staff/Technician 摘要。
2. 今日页并行请求本人资料与任务列表。
3. 确认服务/服务结束使用客户端生成的唯一幂等键调用 API。
4. 网络失败保留当前页面状态，显示可重试提示，不伪造成功状态。
5. 401/账号停用/离职统一清理本地登录态并返回登录页。
6. 403 或跨门店数据直接显示无权限提示，并记录服务端审计。

## 6. 测试与验收

本地：

- 移动端单元/组件测试：登录、路由守卫、任务分组、按钮状态、快记表单和错误态。
- API 合同测试：确认服务、服务结束、快记的权限、门店隔离、幂等和审计。
- 生产构建并检查 320/375/430px 视口无横向滚动，主要按钮可触控。

线上：

- 使用测试技师账号登录独立入口。
- 完成“登录 → 查看任务 → 确认服务 → 服务结束 → 记录服务参考 → 审计”链路。
- 验证管理员/店员不能进入技师移动端，技师不能访问管理后台功能。
- 数据库备份、Manifest 校验、健康检查和容器重启检查全部通过后才允许发布。

## 7. 发布与回滚

- 以服务器实际 `current` 为基线创建 release，仅发布移动技师端静态资源及必要路由配置。
- 首期不执行数据库迁移；若后续需要迁移，必须单独备份并演练恢复。
- 发布后保留上一稳定 release，出现登录、任务或写操作异常时原子切回。
