# hxy-diy 共享记忆

本文件是顾客端、技师端和管理端协作窗口共同读取的项目记忆，只记录已经确认的事实、边界和决策，不复制聊天记录。

## 稳定业务边界

- 智慧宝负责真实开沙发、开房间、派钟、离位、清洁和物理资源释放。
- DIY 负责顾客电子菜单、选单、价格、提交、评价、技师画像记录和审计。
- DIY 普通服务位操作只保留“确认服务”和“服务结束”。
- 已生成智慧宝履约单的服务，不由 DIY 自动释放。
- 技师端不做派单、接单、认领、开房、离位、清洁或物理资源释放。
- 房间按一个独立单位展示，不单独记录房间内床位。

## 数据与权限原则

- Staff 负责登录、角色、门店绑定、账号状态和权限；Technician 负责技师档案、技能、等级、服务资格和提成信息，两者必须保持明确关联关系。
- 所有顾客数据、标签和服务记录按门店隔离，并遵循最小权限原则。
- 技师只能看到完成当前服务所必需的服务位、顾客选单和服务参考字段。
- 所有写操作必须服务端校验角色、门店范围、当前状态和幂等键，并写入审计。
- 顾客画像使用“顾客自述”“服务观察”“服务注意事项”等安全文案，避免医疗诊断式结论。

## 协作规则

- 三个窗口都先读取本文件、`PROJECT-CONTEXT-20260826.md` 和 `WORK-STATUS.md`。
- 每个窗口只修改自己负责的目录；公共文件由主窗口统一修改。
- 技师端窗口同步更新 `docs/workstreams/technician.md`；发布事实统一追加到 `docs/WORK-STATUS.md`。
- 不把浏览器 `localStorage` 当作跨端业务数据源；订单、服务状态和审计以 API/PostgreSQL 为准。
- 发现与本文件冲突的旧文档时，以服务器实际状态、最新测试结果和产品决策为准，并在工作状态中记录更正。
- 三端源码统一位于同一 GitHub monorepo：`admin-react`（管理端）、`diy-web`（顾客端）、`hxy-server`（后端）；各窗口通过任务分支和 Pull Request 协作，不直接推送 `main`。
- Obsidian 以本仓库根目录作为 Vault；共享记忆只通过 `docs/TEAM-MEMORY.md`、`docs/workstreams/*.md` 和 `docs/WORK-STATUS.md` 交换，禁止把聊天记录或本地缓存当作事实来源。
