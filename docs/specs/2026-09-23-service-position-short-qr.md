# 服务位短链接二维码增量规格

## 基本信息

- Feature ID：`SERVICE-POSITION-SHORT-QR`
- 当前状态：`Production Deployed / Field Acceptance Pending`
- 总控负责人：总控窗口
- 执行窗口：顾客端窗口
- 权威 contract：`../contracts/service-position-short-qr-v1.md`

## 业务目标

将每个服务位物料上的完整长查询链接替换为约 58 字符的短 HTTPS 链接，降低二维码模块密度，同时保持既有签名入口、停用轮换、门店隔离、共享选单和评价权限。成功证据包括短码合同测试、完整迁移验证、精确 PR CI、受控生产部署及公网 307 解析。

## 非目标

- 本 PR 不轮换、不打印、不张贴生产 8 个沙发码。
- 不修改顾客菜单、共享选单、会员、价格、订单或评价业务规则。
- 不在管理后台增加新的页面或布局；既有 `qr-link` 接口直接返回短 URL。

## 已确认事实与业务规则

- 现有 v3 token 为 58 字符，但完整 URL 还携带门店、服务位和来源参数；用户已确认新物料应使用更短 URL。
- 短码为 22 字符、128-bit 级不可猜 bearer code，只存 SHA-256 哈希；服务端解析出唯一二维码记录后跳转到现有 v3 签名入口。
- 停用、轮换和换绑沿用 `ServicePositionQr` 状态机；旧短码立即失效。重复读取同一二维码返回同一短 URL，服务位行锁和唯一索引保证并发一致性。
- v2/v3 长码兼容；短码错误、跨店/错床篡改、停码、限流与反馈权限均由合同测试覆盖。

## 权限与数据范围

- 公共短码解析只暴露 307 跳转，不返回门店、顾客、会员、订单或评价数据。
- 管理端 QR 查询、创建、停用、轮换、换绑继续执行现有门店和店长权限。
- 解析审计只记录 HMAC 化来源、二维码、门店和服务位，不记录短码明文。

## API 与数据契约

- 新增 `GET /api/v1/q/{short_code}`。
- `GET /api/v1/admin/service-positions/{room_id}/qr-link` 的 `url` 改为短 URL，兼容保留 `token`。
- `service_position_qrs` 新增可空且唯一索引的 `short_code_hash`；历史记录在管理端读取时惰性补写。

## 跨端影响

| 端/组件 | 是否涉及 | 责任与边界 |
|---|---|---|
| 后端与 OpenAPI | 是 | 短码哈希、解析、审计、限流、迁移及接口契约 |
| 管理后台 | 否 | 本 PR 不改页面；继续消费 `qr-link.url` |
| 技师端 | 否 | 无变化 |
| 顾客端 | 间接 | 浏览器经 307 进入既有 H5，无代码变化 |
| CI / 发布 | 是 | 迁移备份恢复演练、精确 SHA 发布、公网解析验证 |

## 验收标准

- 本地：短 URL 长度/格式、重复读取、扫码进入、反馈入口、跨店错床、停用轮换、限流、旧码兼容及迁移测试通过。
- PR：实现、OpenAPI、contract、共享记忆同 PR，精确 HEAD CI 成功。
- 生产：受控迁移部署成功，健康接口与公网短码 307 行为验证通过；不轮换 8 个生产码。
- 现场：另行生成、打印并逐位真机核对 8 张 A4 海报，不能由 CI 或公网探针替代。
