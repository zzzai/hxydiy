# 荷小悦管理后台与技师端设计规范 v1

日期：2026-10-22
适用范围：`admin-react` 管理后台、技师/店长移动端
设计模式：Operate（运营操作）+ 移动端现场服务

## 1. 设计判断

荷小悦不是一个展示型品牌站，而是门店每天要用的经营工具。设计目标不是“看起来像 spa”，而是：

- 店长在忙碌现场 3 秒内看清今天要关注什么；
- 总部运营在桌面端快速扫描异常、评价和门店数据；
- 技师只做顾客资料、标签和评价相关动作，订单是只读事实；
- 所有状态都能被文字和颜色同时表达，不依赖颜色猜。

视觉方向取“草本账本”：深草本绿作为外壳和导航，温润纸白作为工作区，黄铜色只用于提醒和金额，数字使用等宽数字。拒绝 spa 行业常见的粉色/紫色滤镜，也拒绝通用 SaaS 的渐变大卡片。

## 2. 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--brand-950` | `#0b2822` | 侧边栏、移动端 header |
| `--brand-800` | `#145545` | 深色强调、链接 |
| `--brand-600` | `#16705c` | 主按钮（白字对比度 ≥ 4.5） |
| `--brand-500` | `#1f8f75` | 数据强调、图标 |
| `--brand-100` | `#e6f2ec` | 选中背景、轻提示 |
| `--paper` | `#f3f7f4` | 页面背景 |
| `--surface` | `#ffffff` | 卡片、表格 |
| `--surface-soft` | `#fafcfb` | 次级背景 |
| `--ink-900` | `#132a24` | 主文字 |
| `--ink-700` | `#355248` | 次级文字 |
| `--ink-500` | `#647a71` | 辅助文字 |
| `--line` | `#dee9e3` | 边框 |
| `--line-soft` | `#edf2ef` | 分隔线 |
| `--brass` | `#a86f1f` | 提醒、待处理、金额 |
| `--danger` | `#b54532` | 错误、低分、冲突 |
| `--info` | `#2f6e9b` | 信息、服务中 |

规则：

- 主按钮使用 `--brand-600`，保证白字对比度；`--brand-500` 只用于图形和弱强调。
- 状态不只靠颜色：每个状态必须同时有文字标签。
- 金额使用 `--brass`，只出现在价格和结算相关区域。
- 不使用渐变作为装饰；不使用纯黑 `#000`。

## 3. 字体与数字

- 中文：`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC` 回退。
- 拉丁与数字：`Inter`，数字启用 `font-variant-numeric: tabular-nums`。
- 字号阶梯：`11 / 12 / 13 / 14 / 16 / 18 / 22 / 28`。
- 页面标题 22–28px，卡片标题 15–16px，正文 13–14px，辅助信息 11–12px。
- 正文行高 1.5–1.6，数字和表格 1.35–1.45。
- 不使用全大写英文标签，不用衬线字体强行制造“高级感”。

## 4. 间距、圆角与层级

- 间距阶梯：`4 / 8 / 12 / 16 / 24 / 32`。
- 桌面内容区最大宽度 1440px；页面内边距 24px，卡片内边距 16–20px。
- 圆角：输入与按钮 8px，卡片 12px，移动端卡片 14px，抽屉顶部 20px。
- 阴影只分两级：
  - 静置：`0 1px 2px rgba(15, 45, 36, .04)`；
  - 浮层：`0 12px 32px rgba(15, 45, 36, .12)`。
- 不用“每个元素都带阴影”；分组靠留白和细边框。

## 5. 管理后台结构

```text
┌ 240 深绿侧边栏 ─┬ 64 顶栏：当前页名 / 门店 / 账号 ┐
│ 品牌            │                                   │
│ 经营概览        │ 页面标题 + 说明 + 主操作           │
│ 现场运营        │ 摘要数字（最多 5 个）              │
│ 顾客与增长      │ 内容卡片 / 表格                    │
│ 门店设置        │                                   │
└─────────────────┴───────────────────────────────────┘
```

- 侧边栏使用分组标题，组内不超过 6 项；当前页必须有清晰选中态。
- 顶栏显示“分组 / 页面”上下文，避免用户只看到孤立页面。
- 每个页面只保留一个 `h1` 级标题；页面说明一句话，不写营销文案。
- 摘要数字不超过 5 个；每个数字必须有单位和口径说明。
- 表格：表头 12px 辅助色，行高 ≥ 48px；金额右对齐；操作列固定在右侧。
- 空状态必须给出下一步动作或解释；错误必须带重试。
- 桌面端按钮最小高度 36px；主要操作在页面标题右侧。

## 6. 技师 / 店长移动端

```text
┌ 深绿安全区 header：门店 / 身份 / 更多 ┐
│ 页面标题 + 一句上下文                    │
│ 卡片列表（14px 圆角，16px 内边距）       │
│ 底部 4 tab：今日服务 / 服务记录 / 我的 / 门店 │
└──────────────────────────────────────────┘
```

- header 必须处理 `env(safe-area-inset-top)`；
- 底部 tabbar 处理 `safe-area-inset-bottom`，每个 tab ≥ 52px；
- 所有可点击目标 ≥ 44×44px，相邻目标 ≥ 8px；
- 页面主体内容宽度不超过 560px，桌面预览时不拉伸；
- 订单只读：不展示确认、开始、结束、加选审批等动作；
- 主操作是“查看顾客资料 → 运营标签”和“评价查看/跟进”；
- 抽屉使用底部 sheet，主操作固定在底部，按钮高度 ≥ 46px；
- 错误/空状态不使用仅图标表达，必须有中文说明和恢复动作；
- 支持 `prefers-reduced-motion`，只保留状态变化必要的过渡。

## 7. 组件规则

- **状态标签**：文字 + 色；低分/冲突用 danger，待处理用 brass，服务中用 info，完成用中性。
- **摘要卡**：标签 12px、数值 22–28px、补充说明 12px；点击整卡可进入对应列表。
- **列表卡**：首行状态/时间，第二行主内容，底部金额或元信息；不堆叠超过 4 层信息。
- **按钮**：一个区域只允许一个主按钮；危险操作必须二次确认；移动端按钮宽度优先占满。
- **表单**：标签在输入框上方；错误贴近字段；不使用 placeholder 代替 label。
- **抽屉**：标题说明对象，正文只读信息与动作分区，底部操作固定且安全区留白。
- **导航**：桌面分组、移动 tab；当前项用颜色 + 字重 + `aria-current`。

## 8. 可访问性底线

- 正文对比度 ≥ 4.5:1；大字号 ≥ 3:1。
- 所有交互元素有可见 `:focus-visible`。
- 图标按钮必须有 `aria-label`；装饰图标 `aria-hidden`。
- 页面标题层级连续；不跳级。
- 不使用 hover 作为唯一操作方式；移动端有按下反馈。
- 表格/列表要能被键盘访问；抽屉打开后焦点进入标题，关闭后回到触发点（Ant Design 默认能力基础上补充）。

## 9. 本次落地顺序

1. 先统一 Ant Design token 和全局 CSS token；
2. 管理后台增加顶栏页面上下文、统一页面标题与卡片层级；
3. 移动端统一 header、tabbar、卡片、抽屉、按钮尺寸；
4. 移除订单操作残留，突出标签和评价；
5. 用 Impeccable detector 和前端测试回归，再发布生产。

## 10. 非目标

- 不在本轮重做信息架构或新增业务能力；
- 不更换品牌主色，不引入粉色 spa 视觉；
- 不为了“高级感”增加装饰动画或大面积渐变；
- 不改变订单、评价、标签的业务规则。
