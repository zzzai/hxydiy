# Unslop UI 对荷小悦的适用性

核查日期：2026-11-13。范围是阅读公开技能原文和检查本次菜单界面，不是全站审计或全局安装。

## 结论

能帮助项目 UI，适合作为实现后的轻量检查清单。它擅长识别重复说明、装饰过多、层级不清、卡片过度嵌套和无意义动画。业务是否正确、图片人物结构是否合理、真实手机是否可用，仍分别依靠合同测试、目视检查和现场验收。

公开项目有同名或近名版本，本次区分查阅了：

- [heydamir/unslop](https://github.com/heydamir/unslop)：强调先看实际页面，再确定轻量修整或重做；轻量修整应沿用品牌。作者 Damir Sokolovsky，CC BY 4.0。
- [yuwen-lu/unslop-ui](https://github.com/yuwen-lu/unslop-ui)：防止过多渐变、发光阴影、装饰图标、卡中卡和拖慢阅读的入场动画，MIT。

## 在荷小悦采用的部分

| 检查点 | 荷小悦的做法 |
| --- | --- |
| 信息重复 | 券规则放在领券、券详情和核销场景；菜单保留项目旁价格与适用范围，删除整段重复顶部横幅。 |
| 主次关系 | 项目名称、图片和实际价格优先；辅助解释降为次级文字。 |
| 颜色与背景 | 白色内容、浅绿辅助、深绿主操作，暖金仅少量强调；保持现有品牌，不按固定百分比硬凑颜色。 |
| 组件与间距 | 同类行、按钮、图标保持一致，真实 375/390px 页面检查换行、重叠与触达。 |
| 动效 | 优先让反馈、弹层和导航状态容易理解，不为装饰增加动画。 |
| 内容可信度 | 不用装饰性统计、没有依据的推荐标签或虚构顾客选择填满页面。 |

## 不机械采用的部分

外部技能对字体、圆形图标、卡片和桌面侧栏的绝对限制不是本项目规则。中文手机页面、品牌 IP、门店水彩项目图有自己的用途，不能为了消除所谓模板感把这些全部去掉。既有价格、权限、状态和业务入口也不由视觉技能决定。

## 本次实际落地

移除已领券菜单顶部半价说明及其孤立 CSS；保留五个足疗/SPA主项的持券价、九个排除项目和原核销流程。没有安装全局 skill、引入新前端依赖或改造其他页面。更大范围的导航、会员宣传卡片和控件密度可在后续按页面分别评审，不能视为本次已完成。
