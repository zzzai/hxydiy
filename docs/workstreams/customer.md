# 顾客端工作流

## 负责范围

- 顾客扫码进入、门店与服务位绑定。
- 菜单、项目详情、门店价/团购价/会员价和节省金额。
- 匿名选单、会员登录、提交给前台、服务状态查看和评价。
- 顾客端移动体验、无障碍、刷新/返回/断网恢复和回归测试。

## 明确不做

- 技师派单、接单、开房、离位、清洁和物理资源释放。
- 管理后台权限模型和运营配置页面。
- 智慧宝资源状态的写入。

## 2026-09-05 已完成服务的缓存恢复与再次选购修复

- 产品口径：顾客第一次提交成功后，点击“返回项目列表”应立即进入空白追加草稿，可以继续选购并再次提交；追加提交保留原已提交项目，不覆盖旧项目，也不把旧项目重复回填到当前草稿。
- 状态边界：`submitted` 待服务和 `confirmed + in_service` 沿用同一服务会话追加；已经结束的历史服务不能被新项目改写，服务位释放后应创建新的空白选购会话。
- 根因：顾客端恢复本地 `EntryRecord` 后，即使服务端服务位地图已无活动占用，仍沿用旧会话和旧占用快照；返回项目列表只清空选项，详情页因此继续被旧订单的“已提交前台”只读状态锁住。
- 修复：恢复旧记录和服务结束页返回菜单时，先以服务端实时服务位占用为准；服务位已释放则删除该服务位的旧本地记录，重新创建空白选购会话。服务位仍有活动占用时继续保留旧会话只读，避免把新项目写进已完成订单。
- 回归覆盖：新增“已释放则重开、仍占用则保护旧订单”测试；顾客端测试 `164 passed / 0 failed / 1 skipped`，生产构建通过；服务位和选单闭环后端专项 `66 passed`。
- 当前状态：已随 release `manual-2c3793ea3b95-20260905-1` 发布生产，未执行数据库迁移；仍需在门店授权测试服务位验证“服务结束并释放 → 返回项目列表/刷新 → 空白选购 → 再次提交”。

## 2026-09-05 匿名多次提交价格与后端身份缓存修复

- 现象：未登录顾客多次追加提交后，成功页可能把整单门店价显示为 `0` 或只显示最后一项金额；退出登录或清理前端缓存后，后端仍可能沿用旧会员身份报价。
- 前端根因：成功页在显示“门店价”时读取了随服务端会话身份变化的 `payable_total_cents`，没有固定读取整单 `store_total_cents`；旧异常快照的顶层总价还可能只保留最后一次加选金额。
- 后端根因：手机号登录曾把两年有效的匿名浏览器 Cookie 永久改绑到手机号账号，导致此后新建匿名选单继承会员身份。
- 修复：顾客端按显示价格带分别读取整单门店价/会员价，并为无促销旧快照使用整单小计或明细合计兜底；后端登录只合并历史业务记录，不再改绑匿名浏览器身份，已有错误绑定在下次扫码时自动轮换为新的匿名身份。
- 合同：新增 `docs/contracts/customer-browser-identity.md`，明确浏览器匿名身份、选单显式绑定和多次提交整单重算边界。
- 验证：顾客端测试 `166 passed / 0 failed / 1 skipped`，生产构建通过；价格、选单闭环、登录和服务位后端专项共 `105 passed`。另用全新 Playwright 隔离浏览器打开生产门店入口，确认不继承既有登录缓存并能看到实时服务位图；为避免占用营业服务位，未在生产点击选位或提交测试单。
- 当前状态：已随 release `manual-2c3793ea3b95-20260905-1` 发布生产，未执行数据库迁移；仍需使用授权测试服务位验证“匿名首次提交 → 返回项目列表 → 追加提交 → 整单门店价正确”。

## 2026-09-05 匿名选购清单逐项会员价修复

- 现象：匿名顾客打开“本次待提交”清单时，底栏虽能显示整单会员价与可省金额，但每个服务行只显示门店价，无法在逐项层面看懂会员价差异。
- 根因：清单数据模型仅在会员身份下保留门店价对比字段；非会员身份的会员价没有传递到弹窗渲染层。
- 修复：匿名/非会员的主项目、收费加项和局部调理，在会员价低于门店价时显示“会员价 ¥…”参考；会员继续保持会员价主价与门店价划线对比；免费赠饮和无差价项目不虚构会员价。
- 回归：新增匿名逐项会员价数据测试，顾客端测试与生产构建通过；待发布后用匿名入口核验多项目、加项与局部调理的价格对比和移动端不遮挡。
